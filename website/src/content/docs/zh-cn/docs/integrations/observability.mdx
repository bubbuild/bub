---

两件事分开做：用 Tape 命令看**会话记住了什么**；用 OTLP / Logfire 看**一次 turn 怎么跑**。即使不接外部追踪，Agent 仍会保存选定的对话与运行记录。事件、输出流与持久化记录的区别见[事件](/zh-cn/docs/concepts/events/)。

## 前置条件

- `bub --help` 可用
- 工作区里 `bub run "你有哪些工具？"` 能调用已配置的模型
- 本地跑 Phoenix 需要 Docker 或 Podman
- 安装追踪依赖前，激活[应用虚拟环境](/zh-cn/docs/getting-started/install/#app-install)

## 检查 Tape {#inspect-tape}

```bash
bub run "你有哪些工具？各自适合做什么？"
bub run ",tape.info"
```

期望输出类似：

```text
name: becda04eb9f7369c__065943a03cbe6395
entries: 98
anchors: 2
last_anchor: session/start
entries_since_last_anchor: 44
last_token_usage: 7458
last_token_cache_hit_rate: 72.50%
```

![展示 Bub task run 之后 `tape.info` 输出的终端截图](/docs/observability/tape-info.png)

| 字段 | 用途 |
|---|---|
| `entries` | 会话已积累多少历史 |
| `anchors` / `last_anchor` | 锚点数量与最新上下文边界 |
| `entries_since_last_anchor` | 是否值得 handoff 缩短下次提示词 |
| `last_token_usage` | 最近一次模型路径记录的用量（有则出现） |
| `last_token_cache_hit_rate` | 同次调用中命中缓存的提示词 token 比例（提供商有明细时） |

搜索工具调用、错误或 handoff：

```bash
bub run ",tape.search query=loop.step"
```

需要模型解读时再跑自然语言（依赖凭据）：

```bash
bub run "检查当前 tape，总结上一轮做了什么。"
```

持久化与上下文选择规则见 [Tape](/zh-cn/docs/concepts/tape/)。

## 导出执行轨迹 {#export-traces}

需要看模型 / 工具耗时、并发关系和错误路径时，再导出 trace。Tape 与遥测互相独立。

### Phoenix（OTLP）

```bash
docker run --rm --name bub-phoenix \
  -p 6006:6006 \
  arizephoenix/phoenix:latest
```

UI：`http://localhost:6006`。

安装追踪依赖：

```bash
# 源码仓库
uv sync --extra app --extra trace

# 或已安装的发行版
uv pip install "bub[app,trace]"
```

`trace` 可选依赖包含 OpenTelemetry API/SDK 与 HTTP/protobuf OTLP 导出器。安装 `logfire` 可选依赖时，会同时包含 `app` 与 `trace` 对应依赖；若同时安装，**显式 OTLP 端点仍优先**。

```bash
OTEL_SERVICE_NAME=bub \
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:6006/v1/traces \
OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf \
bub run "你有哪些工具？各自适合做什么？"
```

`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` 是完整 trace URL。也可设 `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:6006`（导出器追加 `/v1/traces`）；trace 专用变量优先。默认协议 `http/protobuf`；headers、timeout、resource attributes、采样用标准 OTEL 环境变量。

显式 OTLP 端点会走直接导出，即使装了 Logfire 也不再配 Logfire。已有追踪提供器会保留；`OTEL_SDK_DISABLED=true` 关闭这条初始化路径。认证用 `OTEL_EXPORTER_OTLP_TRACES_HEADERS`（或 `OTEL_EXPORTER_OTLP_HEADERS`）；Phoenix 项目名可加 `x-project-name=my-project`。

在 Phoenix 中打开 default 项目 → 最近的 trace → 查找 `invoke_agent bub`、`chat <model>`、`execute_tool <tool>`。

![展示 Bub GenAI 遥测通过 OTLP 导出到 Phoenix 的截图](/docs/observability/phoenix-otel.png)

### Logfire

无显式 OTLP 端点时，Bub CLI 启动会配置 Logfire（需安装 `logfire` 可选依赖）。

```bash
unset OTEL_EXPORTER_OTLP_TRACES_ENDPOINT OTEL_EXPORTER_OTLP_ENDPOINT

# 源码仓库
uv sync --extra app --extra logfire

# 或已安装的发行版
uv pip install "bub[logfire]"

logfire auth
logfire projects use
bub run "检查这个仓库并总结它的结构。"
```

部署时设 `LOGFIRE_TOKEN`。在 Logfire Agents 页查找 `bub`。子 Agent 挂在启动它的工具 span 下；同会话通过 `gen_ai.conversation.id` 关联。

### 嵌入与 span 内容

Span 记录模型输入输出、工具参数与最终结果（经结果 hook / spill 之后）、token usage 与错误；内联媒体不上传。模型回退会更新模型属性并把失败尝试记为事件。Token usage 只写在模型 span 上。

Loop step、handoff、spill 等 Tape 事件会附到当前 span；Tape 元数据含 `trace_id` / `span_id`。嵌入时显式初始化：

```python
from bub.tracing import configure_otlp

configure_otlp()  # 读 OTEL_EXPORTER_OTLP_TRACES_ENDPOINT 或 OTEL_EXPORTER_OTLP_ENDPOINT
```

缺少这些可选依赖时跳过追踪。提前停止消费流时用 `contextlib.aclosing(stream)`，以便关闭模型流、Tape 分支和 span。取消会关 span 并设 `bub.cancelled`。

原生 span 提供 Phoenix 所需的 OpenInference 分类与标准 `gen_ai.*` 属性。若仍需把**已保存**的 Tape 投影成 span，可用 contrib 的 [`bub-tapestore-otel`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-tapestore-otel)；迁移时安装本页的 `trace` 或 `logfire` 可选依赖，设 `BUB_TAPESTORE_OTEL_ENABLED=false`，并保留现有 Tape 存储。

## 清理

前台 Phoenix 用 `Ctrl+C`；detached 时：

```bash
docker rm -f bub-phoenix
```
