[Agent Plugins 1.0.0](https://agent-plugins.org/specification) 定义了一种可移植目录：`plugin.json` 描述包，`skills/` 放技能，`mcp.json` 声明 MCP 服务器。`bub-agent-plugins` 把这个目录接入 Bub 的技能发现和 MCP 生命周期，不替换 Python 插件入口点。

下面创建一个包含摘要技能和时间服务器的插件包。验证命令直接调用技能和工具，不需要模型 API 密钥。

开始前，先[安装 Bub 应用](/zh-cn/docs/getting-started/install/#app-install)，并确保 `PATH` 中有 `uvx`。

<Steps>

1. **安装接入插件**

   ```bash
   bub install bub-mcp@main bub-agent-plugins@main
   bub hooks
   ```

   `bub-agent-plugins` 依赖 `bub-mcp`，请安装最新版；即使只使用技能也要显式安装。`bub hooks` 的 `load_state` 和 `provide_channels` 行中应出现 `agent-plugins`。

2. **创建插件包**

   在工作区中创建以下结构：

   ```text
   .agents/plugins/portable-notes/
   ├── plugin.json
   ├── skills/
   │   └── plugin-summary/
   │       └── SKILL.md
   └── mcp.json
   ```

   `plugin.json`：

   ```json
   {
     "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
     "name": "portable-notes",
     "version": "1.0.0",
     "description": "A summary skill and a time server for Bub"
   }
   ```

   `$schema` 和 `name` 为必填字段，`skills/` 和 `mcp.json` 均可选。

   `skills/plugin-summary/SKILL.md`：

   ```markdown
   ---
   name: plugin-summary
   description: Summarize notes into decisions and next actions.
   ---

   Read the supplied notes. List the decisions made, then the remaining actions and their owners.
   If an owner is missing, say that it is unassigned.
   ```

   技能的 `name` 必须与目录名一致。工作区和用户目录中的同名技能优先于插件内技能。

3. **验证技能**

   在工作区运行：

   ```bash
   bub --workspace . run ',skill'
   bub --workspace . run ',skill name=plugin-summary'
   ```

   第一条命令应列出 `plugin-summary`，第二条应打印它的位置和正文。技能不需要后台渠道，因此可以使用 `bub run`。

4. **添加并调用 MCP 服务器**

   `mcp.json`：

   ```json
   {
     "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
     "mcpServers": {
       "time": {
         "type": "stdio",
         "command": "uvx",
         "args": ["mcp-server-time"]
       }
     }
   }
   ```

   可移植格式要求 `$schema`，每个服务器必须声明 `type`：`stdio`、`streamable-http` 或 `sse`。远程服务器使用 `url` 和可选的 `headers`；除回环地址外，URL 必须使用 HTTPS。

   启动聊天界面：

   ```bash
   bub --workspace . chat
   ```

   等待服务器连接后，直接调用时间工具：

   ```text
   ,mcp.portable-notes.time_get_current_time timezone=UTC
   ```

   首次启动时，`uvx` 可能需要下载服务器。看到 `command not found` 时，检查启动日志并等待工具注册后重试。

</Steps>

[配置模型](/zh-cn/docs/app/configure/)后，也可以让模型调用时间工具，或使用 `$plugin-summary` 总结笔记。

## 与现有 MCP 服务器一起使用

两类配置分别管理，互不影响：

| 配置来源 | 生命周期渠道 | 工具名称格式 |
| --- | --- | --- |
| `~/.bub/mcp.json` | `mcp.lifecycle` | `mcp.<server>_<tool>` |
| `<plugin>/mcp.json` | `agent-plugins.mcp` | `mcp.<plugin>.<server>_<tool>` |

因此，两处都可以有名为 `time` 的服务器。`bub mcp add`、`remove` 和 `list` 只管理 `~/.bub/mcp.json`；插件包中的服务器通过启动日志和包含插件名的工具验证。

`bub chat` 和 `bub gateway` 会启动已启用的生命周期渠道，`bub run` 不会。使用 `BUB_ENABLED_CHANNELS` 时，检查是否排除了 `agent-plugins.mcp` 或 `mcp.lifecycle`。

## 配置发现路径与组件

Bub 默认扫描 `<workspace>/.agents/plugins/` 和 `~/.agents/plugins/` 的直接子目录。需要其他位置时，在 `~/.bub/config.yml` 中配置：

```yaml
agent-plugins:
  paths:
    - /opt/agent-plugins/reporting
  auto_discover: true
  skills_enabled: true
  mcp_enabled: true
  data_root: ~/.bub/agent-plugins
```

| 字段 | 作用 |
| --- | --- |
| `paths` | 显式插件根目录，每项直接包含 `plugin.json`；相对路径基于当前工作区 |
| `auto_discover` | 设为 `false` 后只使用显式路径 |
| `skills_enabled` / `mcp_enabled` | 分别启用技能和 MCP 组件 |
| `data_root` | 插件持久化数据根目录，默认 `$BUB_HOME/agent-plugins` 或 `~/.bub/agent-plugins` |

显式路径优先，其次是工作区目录，再其次是用户目录。多个插件包的清单名称相同时，采用第一个有效插件包。

环境变量使用 `BUB_AGENT_PLUGINS_` 前缀，列表值使用 JSON：

```bash
export BUB_AGENT_PLUGINS_PATHS='["/opt/agent-plugins/reporting"]'
export BUB_AGENT_PLUGINS_AUTO_DISCOVER=false
```

stdio 服务器会收到绝对路径形式的 `PLUGIN_ROOT` 和 `PLUGIN_DATA`，默认工作目录是插件根目录。`${PLUGIN_ROOT}` 和 `${PLUGIN_DATA}` 仅在 `args`、`env` 的值和 `cwd` 中展开：

```json
{
  "command": "python",
  "args": ["${PLUGIN_ROOT}/server.py"]
}
```

`PLUGIN_DATA` 指向 `data_root` 下以插件名命名的持久化目录。下载或更新插件包后，重启 Bub 加载新内容。

## 故障排查

| 现象 | 检查项 |
| --- | --- |
| `bub hooks` 中没有 `agent-plugins` | 确认两个接入插件都安装在当前环境，且 `bub-mcp` 版本兼容 |
| 插件包被拒绝 | 检查 `plugin.json` 的 `$schema` 和 `name`，查看 `bub-agent-plugins:` 启动日志 |
| 技能未出现 | 检查 `name` 是否与目录一致、`skills_enabled` 是否开启，以及是否有同名高优先级技能 |
| MCP 工具未出现 | 检查 `mcp.json`、`mcp_enabled`、已启用渠道和连接日志 |
| 技能可用但 MCP 不可用 | 两类组件独立加载；无效服务器会被跳过，不影响技能 |
