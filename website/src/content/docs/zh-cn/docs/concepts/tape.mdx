Agent 需要两样东西。一是自己干过什么的记录，二是下一次模型调用要用的一组消息。Bub 把记录存进 tape，再用你选中的条目拼出模型上下文。两者分开，你就能留下完整历史，同时只发一个短请求。

`core.Agent` 和 `BubAgent` 共用这套机制。两者的默认存储和会话名不一样。

<a id="storage"></a>

## 存储

普通的 `Agent` 默认创建 `InMemoryTapeStore`。历史跟着这个存储一起活，存储没了就没了。要在进程之间保留，传一个文件存储：

```python
from pathlib import Path

from bub.core import Agent
from bub.core.store import FileTapeStore

agent = Agent(store=FileTapeStore(Path("sessions")))
```

每次 `agent.run(..., tape="customer-42")` 用的都是这个存储里名为 `customer-42` 的 tape。名字相同就接着上一次聊，名字不同就分开。`Agent` 原样使用你给的名字。应用有自己的工作区与会话命名规则。

`agent.tape(name)` 让你在一次运行之外看这个 tape。它的写入直接进存储：

```python
async def inspect_history() -> None:
    tape = agent.tape("customer-42")
    messages = await tape.read_messages()
    entries = list(await tape.query().all())
    print(len(messages), "model messages;", len(entries), "stored entries")
```

要自己写存储，实现 `bub.core.store` 里的 `TapeStore` 或 `AsyncTapeStore`。把实例传给 `Agent(store=my_store)` 就行。

| 方法 | 做什么 |
| --- | --- |
| `list_tapes()` | 返回已保存的 tape 名称。 |
| `fetch_all(query)` | 按 `TapeQuery` 的过滤和排序返回条目。 |
| `append(tape, entry)` | 往指定的 tape 追加一条。 |
| `reset(tape)` | 清空指定的 tape。 |

`TapeStore` 用同步方法，`AsyncTapeStore` 用异步方法。Agent 会把同步存储适配成异步调用。持久化和跨进程协调，由你的存储和应用负责。

<a id="context"></a>

## 上下文

tape 的条目有消息、工具调用、工具结果、事件和 anchor。正常记录只追加。要清空历史，得显式调用 `Tape.reset()` 这类操作。

默认的 `TapeContext` 选出最近一个 anchor 之后的会话条目，再转成 Republic 消息：

| 条目 | 模型上下文 |
| --- | --- |
| `anchor` | 默认查询不含它。如果自定义查询选了 anchor，默认选择器会把它转成 assistant 消息。 |
| `message` | 保存的那条消息。 |
| `tool_call` | 一条 assistant 消息，带上这些调用。 |
| `tool_result` | 工具消息，与前面的调用配对。 |
| 其他事件 | 默认选择器跳过。 |

anchor 标出上下文的新起点。`handoff()` 写一个 anchor，前面的条目照旧保留：

```python
async def start_next_phase() -> None:
    await agent.tape("customer-42").handoff(
        name="order-reviewed",
        state={"summary": "Order A123 has shipped; the customer needs tracking details."},
    )
```

这里的 `state` 存在 anchor 上，位置在默认查询的起点之前。要把摘要带进下一阶段，就把它放进下一次 prompt，或者在你的上下文策略里显式选它。要把值装回本轮的可变状态，得自己写加载逻辑。新会话会自动得到一个 `session/start` anchor。

想换一个 anchor，就给 `Agent` 传 `context=TapeContext(...)`。也可以用自己的 `select(entries, context)` 函数。选择器返回 Republic 消息，或者返回它们的 awaitable。`default_tape_context()` 含工具往返；不带 `select` 的 `TapeContext` 用更简单的消息转换。带 `context=False` 的条目，在默认或自定义选择器运行之前就被剔除。

Agent 认出上下文长度错误时，会自动 handoff 一次，然后用更短的上下文重试。要保留前面历史的摘要，就得在 handoff 之前生成。如果剩下的请求还是太大，重试仍会失败。

<a id="state"></a>

## 状态

传给 `agent.run()` 的 `state` 是一个可变字典。本轮的工具、提示词片段和事件处理器共用它。持久化由你的应用负责。长期数据放进自己的存储，或者把选定的事实写进 tape，需要时再读回来。

默认的 [TapeRecorder](/zh-cn/docs/concepts/events/#recording)保存会话往返和一部分生命周期记录。其他变量、自定义事件和决策，要自己记录。

<a id="forks"></a>

## 分支

每次 `agent.run()` 都会给它的 tape 开一个分支。流关闭时，分支把新条目追加到父 tape。抛异常或提前取消也一样。所以一次失败的运行，也可能留下有用的部分历史。

传 `merge_back=False`，退出时丢掉分支的记录。这只影响 tape 写入。工具已经产生的副作用，比如发出的请求、改过的文件，都还在。

自己管一段工作时，用 `agent.session(name, merge_back=...)` 或 `tape.fork_tape(merge_back=...)`。两者默认都在退出时合并，异常退出也合并。

两个运行共用一个 tape，又要看到对方做完的结果，就把它们串起来。会话锁由你的应用提供。[FastAPI 示例](/zh-cn/docs/sdk/web-service/)演示了单进程内的加锁。多个 worker 之间要另外协调。

## Sidecar

`TapeSidecar` 把相关的数据存在另一个 tape 里。挂载的 sidecar 跟着主 tape 一起分支、合并和重置。它的条目不进主上下文。你的应用需要时，用 `Agent(sidecars=...)` 传进去。

Bub 应用给大型工具结果挂了一个 spill sidecar。会话里留一小段预览和一个句柄，agent 可以用 `spill.read` 分段读。合并分支或重置 tape 时，sidecar 的失败单独记录，主 tape 的操作照样完成。spill 的上限在[应用配置](/zh-cn/docs/app/configure/)里。

<a id="application-storage"></a>

## 应用存储

`BubAgent` 用的是 `BubFramework` 给的存储。内置应用用 Bub home 目录下的 `FuzzyFileTapeStore`，通常是 `~/.bub/tapes/`。tape 名称由工作区路径和会话 ID 的哈希拼成。所以同一个会话 ID 在两个工作区里，历史是分开的。

要换存储，应用用 `provide_tape_store`。要选上下文，用 `build_tape_context`。[SQLAlchemy 指南](/zh-cn/docs/integrations/storage/)演示了这条插件路线。直接用 SDK 的服务，按前面说的把实现传给 `Agent(store=...)`。

内置应用会从 tape 记录里恢复部分会话设置。其他本轮状态要自己持久化。
