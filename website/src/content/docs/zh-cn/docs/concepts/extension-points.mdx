从要增加的行为出发。执行新动作需要工具，接收另一种来源的消息需要渠道。这些能力可以一起使用，各自保留清楚的职责。

| 想完成什么 | 使用什么 | 属于哪一层 |
| --- | --- | --- |
| 让 Agent 查询或修改内容 | [工具](/zh-cn/docs/sdk/tools/)。 | 公共内核能力。直接传给 Agent，或在应用中注册。 |
| 观察或拦截模型、工具调用 | [事件处理器](/zh-cn/docs/concepts/events/)。 | Core EventBus；应用插件也可以使用对应的拦截 hooks。 |
| 改变哪些历史进入模型消息 | [TapeContext](/zh-cn/docs/concepts/tape/#context)。 | 直接传给 Agent，或通过应用 hook 提供。 |
| 教会 Agent 一种可复用的工作方法 | [skill](/zh-cn/docs/app/skills/)。 | 由 Bub 应用发现和加载。 |
| 改变应用初始化或消息处理 | [插件](/zh-cn/docs/app/plugins/)。 | BubFramework 及其 hooks。 |
| 接入消息服务 | [渠道](/zh-cn/docs/app/gateway/)。 | 应用的入站与出站路由。 |

## 动作与指令

工具执行 Python 并返回结果。skill 是包含 `SKILL.md` 及可选辅助文件的目录。它的指令可以说明怎样使用工具，其中提到的 Python 工具实现需要单独提供。

普通 Agent 使用你提供的工具和提示词片段。Bub 应用负责发现 skills 和读取 `AGENTS.md`，详见 [Skills](/zh-cn/docs/app/skills/)和[应用工具](/zh-cn/docs/app/tools/)。

工具也可以通过[文本命令](/zh-cn/docs/sdk/tools/#commands)调用，或由 CodeMode 中生成的 Python 调用。这些调用路径共用同一个工具实现。

## 消息与应用状态

渠道接收入站 envelope 并发送出站 envelope。应用从中读取内容、路由信息和会话标识。各 hooks 共用当前轮次的可变 `TurnState` 字典。

[应用消息处理流程](/zh-cn/docs/concepts/turn/)先准备状态和 prompt，再调用 Agent。直接使用 SDK 时，由调用方把 prompt 和 state 传给 Agent。

按需要的能力选择依赖，按宿主的处理方式选择调用入口。Python 服务可以复用应用插件，同时保留自己的请求处理和流接口。[在 Agent 中复用插件](/zh-cn/docs/sdk/app-plugins/)会说明怎样直接使用插件组件，以及如何在宿主中接入 framework hooks。
