选择扩展点前，先看你要增加的是动作、操作说明，还是对运行过程的修改。不同扩展点可以组合，但同一份规则应只保留一个实现。

## 按目标选择 {#choose}

| 目标 | 扩展点 | 接入方式 |
| --- | --- | --- |
| 查询或修改外部系统 | [工具](/zh-cn/docs/sdk/tools/) | `Agent(tools=[...])`，或应用的 `provide_tools()` |
| 给 Agent 一套可复用的操作说明 | [技能](/zh-cn/docs/app/skills/) | 工作区技能目录，或随插件包分发 |
| 把独立子任务交给另一个 Agent 运行 | [子 Agent](/zh-cn/docs/app/subagents/) | 内置 `subagent` 工具，可限制会话、模型、工具和技能 |
| 观察、改写或阻止模型和工具调用 | [Agent 事件](/zh-cn/docs/concepts/events/#call-control) | `agent.events.on()`；应用插件使用拦截 hooks |
| 改变历史到模型消息的转换 | [TapeContext](/zh-cn/docs/concepts/tape/#context) | `Agent(context=...)`，或 `build_tape_context()` |
| 更换历史存储 | [存储集成](/zh-cn/docs/integrations/storage/) | `Agent(store=...)`，或 `provide_tape_store()` |
| 替换模型客户端或执行环境 | 核心组件 | 构造函数参数；应用环境使用 `provide_environment()` |
| 改变消息准备、状态保存或回复发送 | [插件与 Hooks](/zh-cn/docs/app/plugins/) | 插件实现对应 Turn hook |
| 接入新的消息平台或后台服务 | [渠道](/zh-cn/docs/app/gateway/) | 实现 Channel，并通过 `provide_channels(message_handler)` 提供 |
| 让扩展随安装自动生效 | [插件](/zh-cn/docs/app/plugins/) | 在 `bub` entry point 组中注册 |

例如，一个订单插件可以提供：

- 查询和修改订单的工具；
- 说明售后流程的技能；
- 在修改订单前检查权限的拦截 hook；
- 保存订单事件的 Tape 处理器。

它们分别负责执行、流程、约束和记录，不需要把四种逻辑塞进同一个函数。

## 内核组装与应用发现 {#kernel-and-app}

核心层由调用方显式组装：

```python
agent = Agent(
    model=model,
    tools=[order_tool],
    store=store,
    context=context,
)
```

应用层通过 `provide_tools`、`build_tape_context`、`provide_tape_store` 等 hooks 组装同类组件，再由 `BubFramework.load_hooks()` 加载内置实现和已安装插件。

选择依据是**谁负责组装和生命周期**：

- 嵌入已有服务，由宿主管理依赖和资源：使用核心层构造参数。
- 希望安装后自动生效，或分发给别人：使用应用插件。

直接使用核心组件时，也可以按需[复用 Bub 应用](/zh-cn/docs/sdk/reuse-app/)。

## 工具与技能 {#tools-and-skills}

工具是带类型标注的 Python 函数，负责执行动作。技能是包含 `SKILL.md` 及附属文件的目录，负责告诉模型如何完成一类任务。

| 对比项 | 工具 | 技能 |
| --- | --- | --- |
| 内容 | Python 函数和参数 schema | Markdown 指令及附属文件 |
| 用途 | 执行代码、访问外部系统 | 约定流程、约束和操作方法 |
| 加载方式 | 每次模型调用提供可用工具 | 每步列出名称和描述，按技能引用展开正文 |
| 分发方式 | 直接传给 Agent，或由插件注册 | 放在工作区，或随包分发 |

技能中的脚本不会因为文件存在就自动执行。需要运行代码时，仍要通过工具调用；技能可以指导模型何时调用。

同一个工具可以由模型直接调用、由 code mode 中生成的 Python 调用，或通过[文本命令](/zh-cn/docs/sdk/tools/#call-a-tool-without-a-model)调用。三条路径共用处理函数和参数验证，但输出和错误行为可能不同。

## 消息、状态与记录 {#messages-and-state}

| 对象 | 职责 | 生命周期 |
| --- | --- | --- |
| `Envelope` | 传递消息内容、路由和会话信息 | 一条入站或出站消息 |
| `TurnState` | 在 hooks、工具和事件处理器之间共享本轮数据 | 一次 Turn 或 Run |
| Tape | 保存对话、工具往返和显式写入的记录 | 由存储决定，可跨 Turn 和进程 |

新消息来源通过 Channel 产生 `Envelope`。只在当前 Turn 使用的数据放进 `TurnState`；长期事实写入 Tape 或应用存储。并非所有 hooks 都接收 `TurnState`，需要状态时应按对应签名声明参数。

## 检查扩展设计 {#one-owner}

实现前，先明确这些边界：

- **规则只有一个权威来源**：领域约束由工具或领域层保证；统一策略可以放在 hook，不要维护两份可能分叉的判断。
- **指令各有用途**：`AGENTS.md` 提供工作区规则，技能提供按需展开的任务说明。
- **上下文不重复拼接**：`TapeContext` 选择历史，`build_prompt` 准备本次输入。
- **错误有明确去向**：决定异常应传播、记录后跳过，还是转换为工具结果。
- **资源有人关闭**：明确连接和流的生命周期，以及同一会话并发运行时如何协调。
