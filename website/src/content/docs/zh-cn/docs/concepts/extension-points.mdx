先想清楚你要加什么行为。加一个新动作，用工具。加一个新的收消息的地方，用渠道。这些能力可以叠着用，但别让它们干同一件事。

| 你想 | 用 | 它在哪一层 |
| --- | --- | --- |
| 让 agent 读或改某个东西 | [工具](/zh-cn/docs/sdk/tools/)。 | 内核的通用能力。传给 Agent，或者在应用里注册。 |
| 看住或拦下模型、工具调用 | [事件处理器](/zh-cn/docs/concepts/events/)。 | 内核的 EventBus。应用插件可以用对应的拦截 hooks。 |
| 改哪段历史变成模型消息 | [TapeContext](/zh-cn/docs/concepts/tape/#context)。 | 传给 Agent，或者通过应用 hook 提供。 |
| 教 agent 一套可复用的做法 | [技能](/zh-cn/docs/app/skills/)。 | Bub 应用负责发现和加载。 |
| 改应用怎么初始化，或者消息怎么处理 | [插件](/zh-cn/docs/app/plugins/)。 | `BubFramework` 和它的 hooks。 |
| 接一个消息服务 | [渠道](/zh-cn/docs/app/channels/)。 | 应用的入站和出站路由。 |

## 工具与技能

工具跑 Python，返回结果。技能是一个目录，里面有 `SKILL.md`，还可以有别的文件。它的指令可以告诉 agent 怎么用工具。指令里提到的 Python 函数，你自己写，再另外挂上去。

普通的 Agent 只用你给的工具和提示词片段。Bub 应用会去发现技能，也会读 `AGENTS.md`。见 [技能](/zh-cn/docs/app/skills/)和[工具](/zh-cn/docs/app/tools/)。

agent 也可以用一条[文本命令](/zh-cn/docs/sdk/tools/#commands)调工具，或者用 CodeMode 让模型写 Python 来调。这几条路走的是同一个工具实现。

## 消息与状态

渠道收一个入站 envelope，发出站 envelope。应用用 envelope 带内容、路由和会话标识。各个 hooks 共用当前这一轮的 `TurnState` 字典。

[轮次](/zh-cn/docs/concepts/turn/)先把状态和 prompt 准备好，再调 agent。直接用 SDK 的人，自己把 prompt 和 state 交给 Agent。

先按要用的能力选依赖，再按宿主选调用入口。一个 Python 服务可以复用应用插件，同时保留自己的请求处理和流。[在 Agent 里复用插件](/zh-cn/docs/sdk/app-plugins/)讲怎么直接用组件，也讲 framework hooks 在嵌入的宿主里怎么接。
