`bub` 命令行工具由应用层提供，需[安装](/zh-cn/docs/getting-started/install/#app-install) `bub[app]` 可选依赖。本页列出所有内置命令；第三方插件可通过 `register_cli_commands` Hook 注册额外子命令，实际可用命令以 `bub --help` 输出为准。

## 全局选项 {#global-options}

```text
bub [OPTIONS] COMMAND [ARGS]...
```

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--workspace`, `-w` | 路径 | 当前工作目录 | 设置 `BubFramework.workspace`（影响工具默认工作目录、技能发现与相对路径解析） |
| `--version`, `-V` | 开关 | — | 打印当前安装的 Bub 版本号并退出 |
| `--help` | 开关 | — | 显示帮助信息并退出 |

- `--workspace` 不会改变 `BUB_HOME` 数据目录或 `~/.bub/config.yml` 配置文件的位置。
- 不带子命令直接运行 `bub`（或 `bub -w PATH`）时，会执行 `BubFramework.default_command`（内置默认为 `chat`，即启动交互式终端会话）。
- 若当前环境未安装 `app` 可选依赖，运行 `bub` 会打印缺失依赖与安装提示，并以退出码 `1` 退出。

## `bub run` {#bub-run}

处理单条消息的完整 Turn（解析会话、构造提示词、调用模型与工具、保存状态并生成回复），将 `TurnResult.outbounds` 打印到标准输出后退出。不启动 `ChannelManager`。

```text
bub run [OPTIONS] MESSAGE
```

| 参数 / 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `MESSAGE` | 文本 | 必填 | 消息正文；以命令前缀（默认 `,`）开头时直接执行内部命令 |
| `--channel` | 文本 | `cli` | 入站消息渠道标识 |
| `--chat-id` | 文本 | `local` | 入站消息聊天 ID |
| `--sender-id` | 文本 | `human` | 写入 `context.sender_id` |
| `--session-id` | 文本 | `<channel>:<chat-id>` | 显式指定会话 ID（用于跨入口共享历史） |

输出格式：

```text
[channel:chat_id]
<回复正文>
```

示例：

```bash
bub run "Summarize this repository."
bub run --channel web --chat-id demo "Continue the previous topic."
bub run --session-id shared:demo ",tape.info"
```

由于 `bub run` 不启动 `ChannelManager`：

- **不启动常驻后台服务**：`mcp.lifecycle`、`acp-server` 和外部聊天渠道监听器不会启动；
- **不向外部平台发消息**：结果仅打印到终端 stdout；
- **仍初始化核心资源作用域**：`provide_tape_store`、`provide_lifespan` 和 `provide_steering_inbox` 会正常进入并在结束时清理；
- **使用非流式模型调用**：调用 `HookRuntime.run_model`。

注意：当模型阶段报错或未返回文本时，`bub run` 会记录错误日志并打印回退文本，进程仍可能以退出码 `0` 结束。在脚本中调用时，请同时检查 `stderr` 和输出内容，不要仅凭退出码判断模型调用是否成功。

## `bub chat` {#bub-chat}

启动交互式终端会话（REPL），启用 `cli` 渠道，并自动启动所有已启用的 `Lifecycle` 后台服务（如 MCP 连接）。

```text
bub chat [OPTIONS] [INITIAL_PROMPT]
```

| 参数 / 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `INITIAL_PROMPT` | 文本 | — | 可选；进入 REPL 后立即自动发送的第一条消息 |
| `--chat-id` | 文本 | `local` | CLI 聊天 ID |
| `--session-id` | 文本 | `cli_session` | 会话 ID |

- `bub chat` 始终开启流式输出（忽略 `BUB_STREAM_OUTPUT`）。
- 若插件移除了 `cli` 渠道，命令会报错并以退出码 `1` 退出。
- 会话内命令前缀由 `BUB_COMMAND_PREFIX` 控制（默认 `,`），输入 `,help` 查看所有命令。

```bash
bub chat
bub chat "What changed in this repository?"
bub chat --session-id shared:demo
```

## `bub gateway` {#bub-gateway}

启动渠道管理器并常驻运行所有已启用的外部消息渠道（如 Telegram、飞书、Discord）。

```text
bub gateway [OPTIONS]
```

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--enable-channel` | 文本（可重复） | 读取 `BUB_ENABLED_CHANNELS` | 指定要启用的渠道，或用 `!name` 排除某个渠道 |
| `--install` | 开关 | 关闭 | 将网关注册并启动为当前操作系统用户的后台服务 |
| `--uninstall` | 开关 | 关闭 | 停止并卸载已安装的后台网关服务 |

`--install` 与 `--uninstall` 互斥；命令行 `--enable-channel` 优先级高于 `BUB_ENABLED_CHANNELS`。

### 渠道选择规则 {#channel-selection}

`BUB_ENABLED_CHANNELS` 用逗号分隔多个渠道名；`--enable-channel` 可重复传入多次：

| 配置值 | 实际启动的渠道 |
| --- | --- |
| `all`（默认） | 所有 `enabled=True` 且不属于 `Interface` 的渠道与 `Lifecycle` 服务，减去 `!name` 排除项 |
| 显式指定普通渠道名 | 列表中 `enabled=True` 且未被排除的普通渠道，并自动附带所有已启用的 `Lifecycle` 服务 |
| 仅指定 `Lifecycle` 名称 | 仅启动指定的 `Lifecycle` 后台服务 |
| 仅有 `!name` 排除项 | 无任何包含项，报错退出（退出码 `1`） |

- `Interface` 是交互界面渠道（如 `cli`），需显式指定才会启动，`all` 模式下不启动；
- `Lifecycle` 是伴随网关运行的后台服务（如 `mcp.lifecycle`、`agent-plugins.mcp`）；
- 最终无任何可启动渠道时，打印 `No channels are enabled...` 并以退出码 `1` 退出。

```bash
bub gateway
bub gateway --enable-channel telegram
bub gateway --enable-channel telegram --enable-channel discord
bub gateway --enable-channel telegram --enable-channel '!mcp.lifecycle'
```

在 Shell 中使用 `!` 排除渠道时请加单引号（如 `'!mcp.lifecycle'`），防止被 Shell 展开。

### 后台服务安装 {#gateway-service}

| 操作系统 | 安装方式 | 服务位置或行为 |
| --- | --- | --- |
| Linux | systemd 用户服务 | `${XDG_CONFIG_HOME:-~/.config}/systemd/user/bub-gateway.service`（失败自动重启） |
| Windows | Windows 计划任务 | 任务名 `Bub Gateway`，当前用户登录时自启，失败自动重启 |
| macOS | 不支持 `--install` | 请使用 `launchd`、`tmux` 或 [Docker 部署](/zh-cn/docs/app/deploy/) |

- 安装时会记录当前 Python 解释器路径、工作区目录和 `--enable-channel` 参数；更换环境或工作区后需重新运行 `bub gateway --install`。
- Linux 下如需退出 SSH 后保持服务运行，请执行 `loginctl enable-linger "$USER"`。

## `bub onboard` {#bub-onboard}

运行交互式配置向导，生成或更新配置文件（默认 `~/.bub/config.yml`）。

```text
bub onboard [OPTIONS] [PLUGIN_NAME]
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `PLUGIN_NAME` | 文本 | 无 | 可选；仅运行指定插件的 `onboard_config` 向导 |

不传 `PLUGIN_NAME` 时依次运行内置模型向导及所有已注册插件的向导；传入 `PLUGIN_NAME` 时仅运行该插件向导，并跳过末尾的后台服务安装询问。

模型向导写入规则：

| 向导操作 | 写入结果 |
| --- | --- |
| 选择 OpenAI 兼容服务或本地端点 | 写入 `openai:<model>`、`api_base`，并设置 `client_args.api_format: chat` |
| 选择 OpenAI 官方 API 但此前填过非官方地址 | 重置为 `https://api.openai.com/v1` |
| Base URL 留空 | 使用提供商默认地址，不向 YAML 写入空值 |
| Base URL 显式输入 | 写入 YAML（修改了 Base URL 时会自动清空旧 API Key） |
| API Key 留空 | 保留当前地址已有 Key，或依赖运行时环境变量 |
| 选择 Codex | 跳过在线模型列表拉取，直接提示输入模型 ID |

连通性检查仅请求模型列表端点（超时 10 秒），不发起对话生成请求。所有配置合并并通过 `configure.validate` 校验后落盘。成功退出码为 `0`，失败为 `1`。

## `bub install` {#bub-install}

将插件安装到 Bub 托管的 `uv` 项目目录中；不传参数时同步该项目的现有依赖。

```text
bub install [OPTIONS] [SPECS]...
```

| 参数 / 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `SPECS` | 位置参数 | 空 | PyPI 包名、官方扩展名或 Git 仓库地址 |
| `--project` | 路径 | `$BUB_HOME/bub-project`（默认 `~/.bub/bub-project`） | 托管插件项目目录（也可通过 `BUB_PROJECT` 设置） |

支持的包规格格式：

| 格式 | 解析目标 |
| --- | --- |
| `package` | PyPI 包名 |
| `package@ref` | 官方 [`bub-contrib`](https://github.com/bubbuild/bub-contrib) 仓库的 `packages/package` 子目录，固定到分支或标签 `ref` |
| `owner/repo` | `https://github.com/owner/repo.git` |
| `https://github.com/owner/repo.git@ref` | 带版本引用的 Git 仓库 URL（注意简写不支持 `owner/repo@ref`，需传完整 URL） |
| `git@...` 或 `https://...` | 自动添加 `git+` 前缀后交给 `uv` |

`package@ref` 默认使用官方 `bub-contrib` 仓库。若要使用 fork 或镜像，可设置 `config.yml` 顶层的 `contrib_repo`，或用 `BUB_CONTRIB_REPO` 覆盖。可使用 `uv` 支持的 Git URL，例如 `ssh://git@example.com/org/repo.git#subdirectory=plugins/mcp`。`package@ref` 提供 ref；未设置 `#subdirectory=` 时默认使用 `packages/package`，设为 `.` 则使用仓库根目录。私有仓库请使用 SSH 密钥或 Git 凭据助手，不要在 URL 中嵌入凭据。

`owner/repo@ref` 不受支持；为任意 GitHub 仓库固定版本时使用完整 URL。

```bash
bub install bub-mcp@main
bub install bub-discord
bub install https://github.com/owner/repo.git@v1.2.0
bub install
```

插件管理命令底层执行的 `uv` 命令：

| Bub 命令 | 底层 `uv` 命令 |
| --- | --- |
| `bub install`（无参数） | `uv sync --active --inexact` |
| `bub install <specs>` | `uv add --active <requirements>` |
| `bub uninstall <packages>` | `uv remove --active <packages>` |
| `bub update`（无参数） | `uv sync --active --upgrade --inexact` |
| `bub update <packages>` | `uv sync --active --inexact --upgrade-package ...` |

前置条件：系统已安装 `uv`、当前 `bub` 运行在虚拟环境中（`sys.prefix != sys.base_prefix`），且显式传入的 `--project` 目录已存在。

## `bub uninstall` {#bub-uninstall}

从托管插件项目中卸载插件：

```text
bub uninstall [OPTIONS] PACKAGES...
```

```bash
bub uninstall bub-discord
```

## `bub update` {#bub-update}

升级托管插件项目中的插件（不传包名时升级全部已安装插件）：

```text
bub update [OPTIONS] [PACKAGES]...
```

```bash
bub update
bub update bub-mcp
```

升级后请重启正在运行的 `bub chat` 或 `bub gateway` 进程。

## `bub login codex` {#bub-login-codex}

通过 OpenAI Codex CLI 登录并配置 ChatGPT 账号凭据：

```text
bub login codex [OPTIONS]
```

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `--executable` | 文本 | `codex` | Codex CLI 可执行文件路径 |
| `--device-auth` | 开关 | 关闭 | 使用设备码（Device Auth）登录 |
| `--codex-home` | 路径 | `$CODEX_HOME` 或 `~/.codex` | 存放 `auth.json` 的目录 |

登录成功后设置 `BUB_MODEL=codex:<model>` 即可使用，**切勿**同时设置 `BUB_API_KEY`。

## 其他账号登录 {#account-logins}

复用 Grok CLI 或 GitHub CLI 的登录凭据（需先安装对应官方 CLI 工具）：

```bash
bub login grok [--executable grok] [--device-auth]
bub login github-copilot
```

登录后将模型设为 `BUB_MODEL=grok:<model>` 或 `BUB_MODEL=github-copilot:<model>` 即可（无需设置 API Key）。

## `bub plugins` {#bub-plugins}

列出已发现的插件及其所属 Python 包名与版本号：

```text
bub plugins [OPTIONS] [NAMES]...
```

| 参数 / 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `NAMES` | 文本 | 全部插件 | 只查询指定名称的插件 |
| `--version-only` | 开关 | 关闭 | 每行仅输出版本号（无元数据时输出 `-`） |

默认每行输出 `name  distribution version`（加载失败时附带 `(failed: <error>)`）。查询不存在的插件名时退出码为 `1`。

## `bub hooks` {#bub-hooks}

打印所有 Hook 及其绑定的插件列表（用于调试的隐藏命令，不显示在 `bub --help` 中）：

```bash
bub hooks
```

输出格式为 `<hook_name>: <implementation>, ...`，实现名称按 **pluggy 注册顺序**排列。注意注册顺序与运行时执行顺序相反，详见 [Hooks 参考：执行优先级](/zh-cn/docs/reference/hooks/#priority-and-dispatch)。

## 退出码汇总 {#exit-codes}

| 场景 | 退出码 |
| --- | --- |
| 执行成功 | `0` |
| 命令行参数解析错误（Typer） | `2` |
| 缺少 `bub[app]` 依赖、无启用渠道、配置/登录/插件查询失败 | `1` |
| `bub install` / `uninstall` / `update` 中 `uv` 执行失败 | 透传 `uv` 退出码 |
