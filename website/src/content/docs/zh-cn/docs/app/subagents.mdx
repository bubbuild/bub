---
title: 子 Agent
description: 使用内置 subagent 工具将任务委派给后台子 Agent、定义可复用的子 Agent 配置并限制子 Agent 的可用工具。
---

Bub 应用内置了 `subagent` 工具，支持将子任务委派给后台运行的子 Agent。

子 Agent 适合处理**大规模检索、长文档阅读、独立代码审查**等会产生大量中间输出的任务。子 Agent 的工具调用和中间推理都隔离在自己的会话中，只有最后一步生成的最终结论会传回主会话，从而节省主会话的上下文窗口。

## 委派任务 {#delegate}

在 `bub chat` 中，你可以直接要求模型调用子 Agent：

```text
使用 subagent 工具审查身份验证流程：
1. 使用临时会话，只允许使用 fs.read 和 bash；
2. 不要修改文件；
3. 返回审查发现并附带相关文件路径。
```

父 Agent 调用 `subagent` 工具后，子 Agent 会在后台立即启动并返回 `task_id`。子 Agent 在独立循环中完成工具调用与分析后，仅将最后一步的最终文本传回父 Agent。

由于子 Agent 默认只能看到传入的 `prompt`（使用 `session="fork"` 时还能看到调用前的对话），委派任务时的 `prompt` 应当自包含：写清任务目标、期望的返回格式以及限制条件。

你也可以在工作区的 `AGENTS.md` 或技能中写入委派规则（例如「复杂检索或代码审查先委派给只读子 Agent」），让父 Agent 自动委派。

## 会话模式 {#sessions}

`session` 参数决定子 Agent 启动时的初始上下文，以及任务结束后是否保留会话记录：

| `session` 取值 | 行为 | 适用场景 |
| --- | --- | --- |
| `temp`（默认） | 新建空白的 `temp/<task_id>` 临时会话，结束后丢弃 | **最常用**。一次性检索、分析或审查，只需拿回结论 |
| `fork`（别名 `inherit`） | 复制调用那一刻的当前对话快照作为起点，结束后丢弃 | 子任务依赖刚才讨论过的上下文，省去父 Agent 重新复述 |
| 自定义会话 ID 字符串 | 使用指定的固定会话 ID，结束后保留记录 | 需要分多轮跟进的长任务，后续可用 `subagent.send` 继续对话 |

`fork` 仅复制发起调用那一刻的对话快照：子 Agent 看不到父 Agent 此后的新操作，子 Agent 自己的记录也不会合并回父会话。

## 接收结果与管理子任务 {#background}

子 Agent 始终在后台异步运行。父 Agent 可以同时启动多个子 Agent 并行处理子任务，同时自己继续执行其他操作：

```text
启动三个子 Agent，分别检查三个微服务日志中的错误。
你继续处理数据库迁移；等它们全部完成后汇总结论。
```

子任务结束时，结果会以通知消息的形式送达父 Agent：

```text
<subagent-notification task_id="sub-1a2b3c4d" status="completed">
自上次部署以来，支付服务日志中没有发现错误。
</subagent-notification>
```

父 Agent 会在进入下一个 Step 前读到该通知。只要本轮启动的子任务还有未完成的，当前 Turn 就不会提前结束——当父 Agent 没有其他工具要调时，会自动等待下一个子任务完成并汇总结果。若当前 Turn 因报错、取消或达到 `max_steps` 提前中止，未完成的子任务会在该会话的下一轮对话中汇报结果。

父 Agent 也可使用以下工具主动管理后台子任务：

| 工具 | 用途 |
| --- | --- |
| `subagent.wait` | 等待并读取子任务结果，最多等待 `timeout_seconds` 秒（默认 60；设为 `0` 时仅查询状态不阻塞）。不传 `task_ids` 时默认覆盖当前会话所有未读任务。已通过 `subagent.wait` 读取的任务不会再发送通知 |
| `subagent.send` | 向运行中的子任务追加指令（在下一步前生效）；或唤醒已结束的自定义命名会话子任务继续工作 |
| `subagent.cancel` | 终止运行中的子任务 |

进程内同时运行的子 Agent 数量上限由 `BUB_SUBAGENT_MAX_CONCURRENCY` 控制（默认 4），超出上限的任务排队等待。单次运行超时可通过调用参数 `timeout_seconds` 或全局环境变量 `BUB_SUBAGENT_TIMEOUT_SECONDS` 设置。退出 Bub 或执行 `,quit` 会取消所有运行中的子 Agent。

## 定义子 Agent 配置文件（Profile） {#profiles}

如果你经常需要委派固定角色的子任务（如代码审查员、日志排查员），可以把它的模型、工具范围和系统提示词保存为一个**子 Agent 配置（Profile）**。只需在工作区的 `.agents/agents/`（或全局 `~/.agents/agents/`）下创建一个 Markdown 文件：

```markdown title=".agents/agents/reviewer.md"
---
description: 审查代码改动中的 bug 并报告发现，不修改文件
model: openai:gpt-5-mini
tools: [fs.read, bash, tape.search]
skills: []
timeout_seconds: 600
---

你负责代码审查。阅读相关文件，报告具体问题并附上文件路径和行号，绝不修改文件。
```

| 字段 | 说明 |
| --- | --- |
| `description` | **必填**。说明该配置的用途，供父 Agent 判断何时选用 |
| `name` | 可选；默认为去掉 `.md` 后缀的文件名（如 `reviewer`） |
| `model`、`reasoning_effort` | 子 Agent 使用的模型与推理强度 |
| `tools`、`skills` | 允许子 Agent 使用的工具与技能（YAML 列表或逗号分隔字符串） |
| `timeout_seconds` | 子 Agent 超时时间（秒） |

父 Agent 的系统提示词会自动列出已发现的 Profile。模型调用 `subagent(agent="reviewer", ...)` 即可启用该配置；调用时显式传入的参数优先级高于 Profile。工作区下的同名 Profile 会覆盖全局目录中的配置。

## 状态共享与能力边界 {#boundaries}

子 Agent 是父 Agent 实例的一次子运行，两者的共享与隔离边界如下：

| 资源 | 边界 | 说明 |
| --- | --- | --- |
| **Agent 实例** | 共享 | 共享插件 Hooks、模型凭据与 `BubAgent` 配置 |
| **执行环境** | 共享 | 共享工作区目录、本地文件系统、Shell 进程和网络 |
| **模型选择** | 独立配置 | 默认使用 Profile 模型或父模型，可通过 `model` 指定轻量模型 |
| **工具与技能** | 不超出父 Agent | 默认沿用父 Agent 本轮可用的工具与技能，可通过 `allowed_tools`、`allowed_skills` 进一步限制。子 Agent 不能再调用 `subagent` |
| **TurnState** | 浅拷贝 | 复制父 Agent 的 `TurnState`，但使用独立的 steering 收件箱键，发给父 Agent 的引导消息不会被子 Agent 读取 |
| **会话记录** | 按 `session` 模式隔离 | `temp` 和 `fork` 结束后丢弃；自定义命名会话持久保留 |

详细参数定义见 [`subagent` 工具参考](/zh-cn/docs/reference/tools/#subagent)，子任务生命周期事件见[子 Agent 事件](/zh-cn/docs/reference/tools/#subagent-events)。

### 安全边界 {#security-limits}

和父 Agent 一样，子 Agent 同样运行在当前用户权限下的本地环境中，使用时请注意以下边界：

1. **无文件系统隔离**：`session` 仅隔离**对话历史与模型上下文**。子 Agent 对本地文件的修改、执行的命令和发出的网络请求均具有真实系统副作用，退出时不会回滚。
2. **`allowed_tools` 不是强制安全边界**：对话中 `subagent` 的参数由模型生成，因此 `allowed_tools` 仅用于约束模型行为。如需强制拦截高危命令，请使用[工具拦截 Hooks](/zh-cn/docs/app/plugins/#control-a-model-or-tool-call)；如需环境隔离，请配置独立的[执行环境](/zh-cn/docs/app/tools/#environment)。
