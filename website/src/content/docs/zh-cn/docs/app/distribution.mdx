本页只讲打包和发布。要在已有服务中复用 Bub 的配置、插件和完整 Turn，见[复用 Bub 应用](/zh-cn/docs/sdk/reuse-app/)。

这条路径需要[应用依赖](/zh-cn/docs/getting-started/install/#app-install)。

## 发布自有命令 {#publish-a-command}

发行包可以提供自己的命令名，内部调用 Bub 入口：

```python
# src/my_bub/cli.py
def main() -> None:
    from bub.__main__ import main as bub_main

    bub_main()
```

```toml
[project.scripts]
my-bub = "my_bub.cli:main"
```

安装后可以运行 `my-bub chat` 或 `my-bub gateway`。声明 `dependencies = ["bub[app]"]`，并遵循 [0.6 迁移说明](/zh-cn/docs/migration/v0-6/)中的包结构调整。

需要固定工作区时，在调用前切换当前目录，或让用户传入 `--workspace`。

## 分发插件和技能 {#bundle-plugins-and-skills}

一个 wheel 可以同时提供插件入口点和技能命名空间包：

```text
src/
├── my_bub/
│   ├── __init__.py
│   └── ...
└── skills/
    └── my-skill/
        ├── SKILL.md
        └── references/
            └── examples.md
```

`skills/` 属于命名空间包，不要在其中添加 `__init__.py`。技能可以随插件一起分发，也可以独立打包发布。

在 `pyproject.toml` 中配置入口点与 Hatch 构建包含：

```toml
[project.entry-points."bub"]
models = "my_bub.models"
channels = "my_bub.channels:ChannelPlugin"

[tool.hatch.build.targets.wheel]
packages = ["src/my_bub", "src/skills"]
```

入口点遵循[插件注册规则](/zh-cn/docs/app/plugins/#entry-point-forms)，技能编写规范见[技能](/zh-cn/docs/app/skills/)。插件依赖应声明在发行包中。需要把插件安装到 Bub 管理的独立项目时，使用 [`bub install`](/zh-cn/docs/reference/cli/#bub-install)。

## 发布前验证 {#verify-a-release}

在独立虚拟环境中完成以下检查：

1. 从 wheel 安装，而不是从源码目录运行。
2. 运行 `bub hooks`，确认入口点加载成功且没有弃用警告。
3. 运行 `bub run`，验证模型、工具和状态。
4. 运行 `bub chat`，验证技能、命令和生命周期渠道。
5. 按[复用 Bub 应用](/zh-cn/docs/sdk/reuse-app/)接入宿主服务，验证并发、关闭流和退出清理。

干净环境可以暴露漏声明的依赖、不可导入的入口点和只在开发目录可用的配置。
