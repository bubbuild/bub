当你基于 Bub 构建了自定义工具、渠道插件、特定工作流技能，甚至想打造一个专属的定制 CLI 时，可以将它们打包为标准的 Python Wheel，发布到 PyPI 或私有源供团队与用户安装。

常见的三种打包形态：

| 形态 | 包含内容 | 适用场景 |
| --- | --- | --- |
| **扩展插件包** | 插件入口点 + 技能目录 | 为现有 Bub 应用补充工具、渠道或技能 |
| **定制 CLI** | 自定义命令脚本（如 `my-bub`） | 封装专属命令名或固定默认工作区 |
| **一体化套件** | 自有命令 + 插件 + 技能 | 交付开箱即用的垂直领域 Agent |

:::note
本页介绍如何构建**独立可安装的 Python 包**。若要在现有 Web 服务或后端代码中嵌入 Bub，请阅读[复用 Bub 应用](/zh-cn/docs/integrations/reuse-app/)。
:::

## 封装自有 CLI 命令 {#publish-a-command}

发行包可以注册自己的命令名，并在内部调用 Bub 的 CLI 入口，为你的 Agent 打造专属品牌或固定默认工作区：

```python title="src/my_bub/cli.py"
import os
from pathlib import Path
from bub.__main__ import main as bub_main


def main() -> None:
    # 可选：设置默认工作区（用户传入的 --workspace 仍可覆盖它）
    if workspace := os.getenv("MY_BUB_WORKSPACE"):
        os.chdir(Path(workspace).expanduser())

    bub_main()
```

在 `pyproject.toml` 中通过 `[project.scripts]` 声明命令：

```toml title="pyproject.toml"
[project.scripts]
my-bub = "my_bub.cli:main"
```

安装完成后，用户就可以直接运行 `my-bub chat`、`my-bub run` 或 `my-bub gateway`，所有原生子命令和 `--workspace` 等参数都会一并生效。

## 同时打包插件与技能 {#bundle-plugins-and-skills}

一个 Wheel 包可以同时包含 CLI 命令、插件入口点和 `skills` 命名空间包：

<FileTree>

- my-bub/
  - **pyproject.toml**
  - src/
    - my_bub/
      - \_\_init\_\_.py
      - **cli.py** # 自定义 CLI 入口
      - **plugin.py** # 插件与 Hook 实现
      - tools.py # 自定义工具
    - **skills/** # 技能命名空间包（切勿创建 \_\_init\_\_.py）
      - repo-reviewer/
        - SKILL.md
        - references/
          - guidelines.md

</FileTree>

:::caution[技能目录不得包含 `__init__.py`]
`src/skills/` 必须作为 **PEP 420 隐式命名空间包** 打包，**切勿**在 `src/skills/` 下创建 `__init__.py`。只有保持隐式命名空间结构，该包中的技能才能与 Bub 内置技能及其他插件包中的技能共同合并到 `skills.__path__` 下。
:::

### 配置 `pyproject.toml` {#configure-packaging}

```toml title="pyproject.toml" mark={14-15,17-18,20-21}
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "my-bub"
version = "0.1.0"
description = "My Custom Bub Agent Distribution"
requires-python = ">=3.12"
dependencies = [
    "bub[app]>=0.6.0",
]

[project.scripts]
my-bub = "my_bub.cli:main"

[project.entry-points."bub"]
my_plugin = "my_bub.plugin:plugin"

[tool.hatch.build.targets.wheel]
packages = ["src/my_bub", "src/skills"]
```

配置要点：

1. **依赖 `bub[app]`**：核心包 `bub` 仅含内核，CLI、插件和技能加载均需 `bub[app]`（见 [0.6.0 升级说明](/zh-cn/docs/migration/v0-6/)）。
2. **声明 `"bub"` 入口点**：在 `[project.entry-points."bub"]` 下注册插件（语法见[入口点形式](/zh-cn/docs/app/plugins/#entry-point-forms)）。
3. **打包 `src/skills`**：在 `[tool.hatch.build.targets.wheel]` 的 `packages` 中显式列入 `"src/skills"`。

## 构建与安装 {#build-and-distribute}

使用 `uv` 构建 Wheel 和源码包：

```bash
uv build
```

构建产物位于 `dist/` 目录下。下游用户可通过以下方式安装：

- **作为独立 CLI 工具安装**：`uv tool install my-bub`
- **作为 Bub 托管插件安装**：[`bub install <package>`](/zh-cn/docs/reference/cli/#bub-install)

## 发布前验证 {#verify-a-release}

发布到公开或生产环境前，建议在全新的虚拟环境中从构建好的 `.whl` 文件安装并走一遍验证：

<Steps>

1. **创建干净环境并安装 Wheel**：
   ```bash
   uv venv .test-env && source .test-env/bin/activate
   uv pip install dist/*.whl
   ```

2. **验证插件加载**：
   ```bash
   my-bub hooks
   ```
   确认输出中包含你的插件标识，且无导入报错。

3. **验证技能发现**：
   ```bash
   my-bub run ",skill"
   my-bub run ",skill name=repo-reviewer"
   ```
   确认打包的技能已被发现且正文能正常展开。

4. **验证对话与工具调用**：
   ```bash
   my-bub run "测试模型与自定义工具"
   my-bub chat
   ```

</Steps>
