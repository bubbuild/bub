工具为 Bub 应用执行具体动作。应用已经内置文件、Shell、Web、Tape 和子 Agent 等工具，也可以通过插件添加自己的工具。函数签名、结果渲染和 `ToolContext` 见[自定义工具与 code mode](/zh-cn/docs/sdk/tools/)，内置工具的参数与默认值见[内置工具参考](/zh-cn/docs/reference/tools/)。

## 内置工具目录 {#builtin-tools}

模型可以根据任务自行选择工具，你也可以用命令前缀直接调用。模型看到的名称会把点替换为下划线，例如 `fs.read` 对应 `fs_read`。

| 任务 | 工具 | 说明 |
| --- | --- | --- |
| 运行进程 | `bash` | 执行 Shell；支持工作目录、超时和后台运行 |
| 管理后台进程 | `bash.output`、`bash.kill` | 增量读取输出、终止进程 |
| 读写文件 | `fs.read`、`fs.write`、`fs.edit` | 分页读取、写入整个文件、替换文本 |
| 获取网页 | `web.fetch` | 发起 GET 请求，优先请求 Markdown；网页搜索使用搜索插件 |
| 使用技能 | `skill` | 列出技能，或读取指定技能正文 |
| 发现延迟工具 | `tool.describe` | 加载工具定义，从下一个 Step 开始调用 |
| 检查会话 | `tape.info`、`tape.search`、`tape.anchors` | 查看用量、搜索记录、列出 anchor |
| 管理上下文 | `tape.handoff`、`tape.reset` | 移动上下文起点；重置时可先归档 |
| 委派任务 | [`subagent`](/zh-cn/docs/app/subagents/) | 使用独立或指定会话运行子 Agent |
| 执行组合逻辑 | `run_code` | 在 code mode 中用 Python 组合工具调用 |
| 读取大型结果 | `spill.read` | 按块读取已移出主上下文的大型工具结果 |

`model`、`reasoning_effort`、`code_mode`、`help` 和 `quit` 仅作为命令提供，不直接暴露给模型。终端中的使用方式见[终端](/zh-cn/docs/app/terminal/#commands)，后台进程示例见[后台进程](/zh-cn/docs/app/terminal/#background-shell)。

自定义工具的创建、`provide_tools` 注册和插件加载见[提供工具](/zh-cn/docs/app/plugins/#provide-tools)。注册后，可以按下文策略限制本次 Turn、延迟加载定义或选择执行环境。

## 限制本次 Turn 的工具 {#allowed-tools}

调用 `BubAgent.run_stream()` 时传入 `allowed_tools`：

```python
stream = await agent.run_stream(
    session_id="customer-42",
    prompt=["查询订单 A123"],
    allowed_tools={"orders.get"},
)
```

它接受运行时名称或模型别名。`None` 允许全部实例工具，空集合不允许任何工具，未知名称抛出 `ValueError`。

筛选作用于模型直接调用和 code mode。逗号命令直接使用 Agent 实例的工具，不受此列表限制；需要同时约束命令时，使用[工具调用 decision](/zh-cn/docs/app/hooks/#control-a-model-or-tool-call)。

## 延迟加载工具定义 {#deferred-tools}

工具较多时，设置 `deferred=True`，避免把完整定义都放进初始模型请求：

```python
from bub import tool


@tool(name="orders.get", deferred=True)
def get_order(order_id: str) -> dict[str, str]:
    """Look up an order by id."""
    return {"id": order_id, "status": "shipped"}
```

`BubAgent` 在系统提示词中列出延迟工具的名称，并提供 `tool.describe`。模型调用它加载定义，从下一个 Step 开始可以直接调用工具。

加载记录写为 Tape 的 `tool.loaded` 事件，因此后续 Step 和 Turn 都能继续使用该工具，直到 Tape 重置。`allowed_tools` 同时限制工具的展示与加载。

code mode 中，允许使用的 `auto` 和 `code` 工具可以直接由 Python 调用；延迟加载只影响仍直接提供给模型的工具。

## 使用 code mode {#code-mode}

在会话中启用 code mode：

```text
,code_mode enable=true
```

设置从下一个 Turn 开始生效，并记录在 Tape 中供重启后恢复。使用 `,code_mode enable=false` 关闭。直接调用 `BubAgent` 时，可为本次运行设置 `state["code_mode"] = True`。

`run_code` 可用时，应用按 `exposure` 选择工具：

| `exposure` | code mode 关闭 | code mode 开启 |
| --- | --- | --- |
| `auto` | 直接提供给模型 | 通过 `run_code` 调用 |
| `direct` | 直接提供给模型 | 仍直接提供，不出现在 `tools.*` 下 |
| `code` | 不提供给模型 | 通过 `run_code` 调用 |
| `command` | 仅命令调用 | 仅命令调用 |

`run_code` 不在允许工具集合中时，本次 Turn 按 code mode 关闭的规则处理。

应用将 Python 工具声明写入 `<BUB_HOME>/codemode/`，并把文件路径加入系统提示词。代码使用 `await tools.orders_get(order_id="123")` 调用工具，仍经过应用的拦截 hooks。

code mode 使用会话的执行环境和模型配置。Republic bridge 在宿主侧处理模型凭据；默认 `LocalEnvironment` 仍以宿主用户权限运行生成的代码，不是安全沙箱。核心 Agent 需要[显式组合 CodeMode](/zh-cn/docs/sdk/tools/#compose-tools-with-codemode)。

## 选择执行环境 {#environment}

内置 `bash`、`bash.output`、`bash.kill`、`fs.*` 和 `run_code` 使用会话的 `Environment`。默认是运行在宿主上的 `LocalEnvironment`。

插件通过 `provide_environment(session_id, workspace)` 提供其他环境。Framework 为每个会话缓存一个环境，并在 `framework.running()` 退出时关闭。接口见[执行环境](/zh-cn/docs/sdk/tools/#choose-an-execution-environment)。

自定义工具通过 `bub.builtin.environment.environment_from_state(context.state)` 取得环境。普通 Python 工具函数仍在宿主进程执行，只有显式调用环境的操作才进入该环境。

## 为工具提供操作说明 {#instructions}

工作区通用约定放在 `AGENTS.md`，按任务加载的流程放在[技能](/zh-cn/docs/app/skills/)中。技能可以告诉模型何时调用工具，Python 函数负责实际执行。

使用者也可以通过命令前缀直接调用工具，不经过模型。语法见[文本命令](/zh-cn/docs/sdk/tools/#call-a-tool-without-a-model)。
