Bub 既能在本地终端里随开随用（见[终端交互](/zh-cn/docs/app/terminal/)），也可以部署到服务器上常驻运行：

- **常驻消息网关**：7×24 小时监听 Telegram、飞书等渠道并响应消息；
- **容器隔离沙箱**：在容器内运行开发工具链并通过 `bub chat` 交互，隔离宿主机环境。

两种部署方式对比：

| 方式 | 适用场景 | 特点 |
| --- | --- | --- |
| **Docker Compose**（推荐） | 云服务器、VPS、NAS、本地容器 | 自带 Python、`uv`、Git、Node.js 等完整工具链，环境隔离，易于备份升级 |
| **Daemon 系统服务** | 已有 Python 环境的 Linux / Windows 主机 | 资源占用低，通过 `bub gateway --install` 一键注册为后台服务 |

## 开始之前 {#before-you-start}

1. **配置模型**：在 `.env` 中配置 `BUB_MODEL` 和 `BUB_API_KEY`（见[配置](/zh-cn/docs/app/configure/)）。
2. **配置渠道白名单**：接入聊天平台时**必须配置白名单**（如 `BUB_TELEGRAM_ALLOW_USERS`），防止未授权访问。
3. **持久化数据目录**：会话 Tape 和托管插件保存在数据目录（宿主机 `~/.bub`，容器内 `/data`），请确保挂载到持久卷。

:::caution[安全提示]
生产环境中切勿将白名单留空！若白名单为空，任何能搜到机器人的用户均可调用你的 Agent 工具。
:::

## Docker Compose 部署 {#docker-compose}

官方镜像 `ghcr.io/bubbuild/bub` 已内置 Python 3.12、`uv`、Git、Node.js 和 pnpm。

### 1. 准备配置文件 {#configure}

下载 [`docker-compose.yml`](https://github.com/bubbuild/bub/blob/main/docker-compose.yml) 和 [`env.example`](https://github.com/bubbuild/bub/blob/main/env.example)：

```bash
mkdir -p bub-deploy && cd bub-deploy
curl -O https://raw.githubusercontent.com/bubbuild/bub/main/docker-compose.yml
curl -O https://raw.githubusercontent.com/bubbuild/bub/main/env.example
cp env.example .env
```

编辑 `.env`：

```bash title=".env"
# 模型
BUB_MODEL=openrouter:openrouter/free
BUB_API_KEY=sk-or-...

# 渠道（以 Telegram 为例）
BUB_TELEGRAM_TOKEN=123456789:your-telegram-bot-token
BUB_TELEGRAM_ALLOW_USERS=123456789,your_telegram_username

# 可选：宿主机数据目录与工作区路径
# BUB_HOME_HOST=~/.bub
# BUB_WORKSPACE_PATH=.
```

### 2. 检查挂载目录 {#volumes}

默认 `docker-compose.yml` 挂载三个目录：

```yaml title="docker-compose.yml"
volumes:
  - ${BUB_WORKSPACE_PATH:-.}:/workspace
  - ${BUB_HOME_HOST:-${HOME}/.bub}:/data
  - ${BUB_AGENT_HOME:-${HOME}/.agents}:/root/.agents
```

| 容器路径 | 宿主机路径 | 用途 |
| --- | --- | --- |
| `/workspace` | `BUB_WORKSPACE_PATH`（默认当前目录） | **工作区**：Agent 读写文件和执行命令的目录 |
| `/data` | `BUB_HOME_HOST`（默认 `~/.bub`） | **数据目录**（`BUB_HOME=/data`）：保存 Tape 历史与托管插件 |
| `/root/.agents` | `BUB_AGENT_HOME`（默认 `~/.agents`） | **全局技能目录**：跨工作区复用的技能 |

:::danger[切勿挂载敏感目录]
工作区决定了 Agent 可访问的文件范围。**切勿**将宿主机根目录 `/` 或包含密钥的目录挂载到 `/workspace`。
:::

### 3. 启动容器 {#start}

<Tabs>
  <TabItem label="官方镜像（推荐）">
    ```bash
    docker compose pull
    docker compose up -d
    docker compose logs -f app
    ```

    生产环境建议在 `.env` 中固定镜像版本（如 `BUB_IMAGE=ghcr.io/bubbuild/bub:0.6.0`）。
  </TabItem>
  <TabItem label="本地构建">
    ```bash
    docker compose up -d --build
    ```
  </TabItem>
  <TabItem label="docker run">
    ```bash
    docker run -d --name bub --restart unless-stopped \
      --env-file .env \
      -e BUB_HOME=/data \
      -v "$PWD":/workspace \
      -v "$HOME/.bub":/data \
      -v "$HOME/.agents":/root/.agents \
      ghcr.io/bubbuild/bub:latest

    docker logs -f bub
    ```
  </TabItem>
</Tabs>

### 4. 验证状态 {#verify}

查看容器状态与日志：

```bash
docker compose ps
docker compose logs -f app
```

Telegram 渠道启动成功时会打印：

```text
telegram.start allow_users_count=1 allow_chats_count=0 proxy_enabled=False
telegram.start polling
```

### 5. 进入容器交互式对话 {#chat}

Compose 默认开启了 `stdin_open` 与 `tty`。即使容器正在后台运行网关，你也可以随时进入容器开启交互式对话：

```bash
docker compose exec -it app bub chat
```

这让你能在云端完全隔离的沙箱环境中，直接调用预装的工具链与 Agent 结对编程。

### 6. 自定义启动脚本与依赖 {#entrypoint}

容器启动时，`entrypoint.sh` 按顺序执行：

<Steps>

1. 若 `/workspace/bub-reqs.txt` 存在，执行 `uv pip install` 安装额外 Python 依赖；
2. 激活虚拟环境并运行 `bub install`，同步 `/data/bub-project` 中的托管插件；
3. 若 `/workspace/startup.sh` 存在则执行该脚本，否则执行 `bub gateway`。

</Steps>

如需自定义启动参数，可在工作区创建 `startup.sh`（注意使用 `exec` 以便传递停止信号）：

```bash
#!/bin/bash
# /workspace/startup.sh
set -euo pipefail
exec /app/.venv/bin/bub gateway --enable-channel telegram
```

### 7. 在容器内管理插件 {#plugins}

托管插件保存在持久卷 `/data/bub-project` 中，可直接安装或更新，无需重建镜像：

```bash
docker compose exec app bub install https://github.com/owner/repo.git@v1.2.0
docker compose exec app bub update
docker compose restart app
```

### 8. 备份与升级 {#upgrade}

升级前建议先停止容器并备份数据目录：

```bash
docker compose stop app
tar -czf "bub-data-$(date +%Y%m%d-%H%M%S).tar.gz" "$HOME/.bub"
cp .env ".env.bak-$(date +%Y%m%d-%H%M%S)"

docker compose pull
docker compose up -d
```

若需回滚，只需在 `.env` 中换回旧 Tag（如 `BUB_IMAGE=ghcr.io/bubbuild/bub:0.6.0`）并重新启动。

## Daemon 系统服务模式 {#daemon}

在已有 Python 环境的 Linux 或 Windows 主机上，可使用 `bub gateway --install` 一键注册为系统后台服务：

- **Linux**：注册为 systemd 用户级服务 `~/.config/systemd/user/bub-gateway.service`。
- **Windows**：注册为当前用户的计划任务（登录自启，失败自动重启）。
- **macOS**：暂不支持 `--install`，建议使用 `launchd`、`tmux` 或上述 Docker 方案。

### 1. 安装服务 {#daemon-install}

在包含 `.env` 的工作区目录下执行：

```bash
uv venv && source .venv/bin/activate
uv pip install 'bub[app]'
bub gateway --install
```

安装程序会自动记录当前的 Python 解释器路径、工作区目录与环境变量。

### 2. 管理服务（Linux） {#daemon-manage}

Linux 用户注销 SSH 后，默认会挂起用户级服务。如需保持 7×24 小时运行，请启用 linger：

```bash
loginctl enable-linger $USER
```

常用 `systemctl` 命令：

```bash
systemctl --user status bub-gateway
journalctl --user -u bub-gateway -f
systemctl --user restart bub-gateway
systemctl --user stop bub-gateway
```

### 3. 卸载服务 {#daemon-uninstall}

如需移除后台服务，运行：

```bash
bub gateway --uninstall
```

## 安全检查清单 {#security-checklist}

- **配置白名单**：设置 `BUB_TELEGRAM_ALLOW_USERS` 或 `BUB_TELEGRAM_ALLOW_CHATS`。
- **最小化工作区目录**：仅挂载必要的项目目录，隔离主机密钥与系统目录。
- **限制最大步数**：设置 `BUB_MAX_STEPS`（默认无上限 `sys.maxsize`，生产环境建议设为 `50` 左右），防止死循环耗尽额度。
- **保护密钥**：通过 `.env` 或环境变量注入凭据，切勿提交到 Git 仓库。
- **定期备份**：定期备份 `~/.bub`（或容器 `/data`）中的 Tape 记录。
