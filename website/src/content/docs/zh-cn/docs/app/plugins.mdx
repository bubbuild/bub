插件通过 hooks 改变 Bub 应用的行为。Python 包在 `bub` 入口点组中声明插件对象，Bub 导入它，并把其中的 hook 实现接入应用。

下面先写一个不需要模型凭据的回声插件，验证完整的创建、安装和运行流程。复用现有插件见[复用应用插件](/zh-cn/docs/sdk/reuse-plugins/)。

## 创建一个插件 {#create-a-plugin}

准备 Python 3.12+ 与 [uv](/zh-cn/docs/getting-started/install/)，创建以下项目：

```text
bub-echo-plugin/
├── pyproject.toml
└── src/
    └── bub_echo_plugin/
        ├── __init__.py
        └── plugin.py
```

`src/bub_echo_plugin/__init__.py` 可以留空。在 `pyproject.toml` 中声明包和入口点：

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "bub-echo-plugin"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["bub[app]"]

[project.entry-points."bub"]
echo = "bub_echo_plugin.plugin:echo_plugin"

[tool.hatch.build.targets.wheel]
packages = ["src/bub_echo_plugin"]
```

入口点的键 `echo` 是插件名，值指向要加载的对象。在 `src/bub_echo_plugin/plugin.py` 中实现模型阶段：

```python
from bub import hookimpl


class EchoPlugin:
    @hookimpl
    def run_model(self, prompt, session_id, state):
        return f"[echo:{session_id}] {prompt}"


echo_plugin = EchoPlugin()
```

`run_model` 替换内置模型阶段并返回纯文本，消息准备、状态保存和回复发送仍由其他 hooks 完成。

## 安装并运行 {#install-and-run}

在插件项目中同步环境，然后检查 hook 报告：

```bash
uv sync
uv run bub hooks
```

`uv sync` 会以可编辑模式安装当前项目。`bub hooks` 应在 `run_model` 下列出 `echo`，内置 Agent 则出现在 `run_model_stream` 下。

```bash
uv run bub run "hello from my plugin"
```

没有其他更高优先级的模型实现时，输出包含：

```text
[echo:cli:local] hello from my plugin
```

没有看到 `echo` 时，依次检查：

1. 安装插件的环境是否就是运行 `bub` 的环境；
2. `[project.entry-points."bub"]` 的组名和模块路径是否正确；
3. 启动日志是否记录了插件导入失败。

修改入口点元数据后要重新安装。`echo` 已出现但回复来自别处时，检查其他模型 hook 及其[优先级](/zh-cn/docs/reference/hooks/#priority-and-dispatch)。

Bub 先注册内置实现，再注册入口点插件。相同优先级下，后注册的实现先执行；`tryfirst` 和 `trylast` 可以调整顺序。

## 选择入口点形式 {#entry-point-forms}

| 入口点目标 | 行为 | 适用情况 |
| --- | --- | --- |
| `bub_myplugin.plugin` | 注册模块 | hooks 是模块级函数 |
| `bub_myplugin.plugin:plugin` | 注册已有实例 | hooks 共享对象状态 |
| `bub_myplugin.plugin:MyPlugin` | 调用类或工厂并注册返回值 | hooks 需要访问 `BubFramework` |

入口点的值可调用时，Bub 会把当前 `BubFramework` 传给它：

```python
from bub import BubFramework, hookimpl


class MyPlugin:
    def __init__(self, framework: BubFramework) -> None:
        self.framework = framework

    @hookimpl
    def build_prompt(self, message, session_id, state):
        return f"Describe the workspace at {self.framework.workspace}."
```

`build_prompt` 会替换模型输入。实际扩展应选择职责匹配的 hook，见[应用 Hooks](/zh-cn/docs/app/hooks/)。

## 提供工具 {#provide-tools}

新插件应通过 `provide_tools` 显式提供 `@tool` 对象：

```python
from bub import hookimpl, tool
from bub.core.tools import Tool


@tool(name="orders.get")
def get_order(order_id: str) -> dict[str, str]:
    """Look up an order by id."""
    return {"id": order_id, "status": "shipped"}


class OrdersPlugin:
    @hookimpl
    def provide_tools(self) -> list[Tool]:
        return [get_order]
```

`BubAgent` 在构造时取得当前工具快照。运行期间新增工具，需要更新该实例的 `tools` 字典；新 Agent 会重新收集。

旧插件依赖入口点加载时的 `@tool` 自动收集，且未实现 `provide_tools` 时，工具仍会注册并产生弃用警告。新插件不要使用这条回退路径。工具参数、延迟加载和 code mode 见[应用工具](/zh-cn/docs/app/tools/)。

## 提供常驻服务 {#lifecycle}

MCP 客户端、调度器等组件需要随进程启动，而不是响应某条消息。实现 `Lifecycle`，并和其他渠道一样通过 `provide_channels` 提供：

```python
from bub.channels.base import Lifecycle


class MyRuntime(Lifecycle):
    name = "myapp.lifecycle"

    async def start(self, stop_event) -> None:
        await self._connect(stop_event)

    async def stop(self) -> None:
        await self._close()
```

生命周期渠道随渠道运行时启动和退出，不接收消息：

- 出现在 `--enable-channel` 可选的渠道名中；
- 显式列出普通渠道时，已启用的 `Lifecycle` 仍会自动附加；
- 可以用 `!name` 排除，例如 `--enable-channel '!mcp.lifecycle'`；
- `bub run` 不启动渠道，因此也不会启动常驻服务。

完整示例见 [`bub-mcp`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-mcp) 和 [`bub-schedule`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-schedule)。

## 分享插件 {#share-a-plugin}

一个发行包可以同时提供插件、渠道和[技能](/zh-cn/docs/app/skills/#include-skills-in-a-wheel)：

```toml
[project.entry-points."bub"]
orders = "bub_orders.plugin"

[tool.hatch.build.targets.wheel]
packages = ["src/bub_orders", "src/skills"]
```

通用 wheel 构建、CLI 打包和发布前验证见[嵌入与分发](/zh-cn/docs/app/distribution/)。Agent Plugins 则使用 `plugin.json`、技能和 MCP 服务器定义，见[加载 Agent Plugins](/zh-cn/docs/integrations/agent-plugins/)。

## WASM 插件（实验性） {#wasm-plugins}

[`bub-extism`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-extism) 通过 Extism 把 WebAssembly 模块导出函数暴露为 hook，因此插件也可以用其他语言编写：

```bash
bub install bub-extism@main
bub hooks
```

`extism.json` 指定模块文件和 hook 映射：

```json
{
  "plugins": {
    "prompt": {
      "manifest": { "wasm": [{ "path": "go-build-prompt.wasm" }] },
      "wasi": true,
      "hooks": { "build_prompt": "build_prompt" }
    }
  }
}
```

```bash
export BUB_EXTISM_CONFIG_PATH=./extism.json
bub run "Say hello from a prompt built outside Python."
```

并非所有 hook 都支持 WASM，参数也必须跨过 Python 与 WASM 的边界。使用前核对[插件 README](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-extism) 的支持列表与示例。
