本页说明 `core.Agent` 的常用构造参数和运行选项。完整示例见[在 Python 中运行 Agent](/zh-cn/docs/sdk/)。

## 选择模型 {#choose-a-model}

`Agent(model=...)` 设置默认模型，`agent.run(model=...)` 只覆盖当前运行。运行需要模型而两处都没有提供时，会抛出 `ValueError`。

Republic 模型由调用方管理生命周期：

```python
async with republic.get_model(
    "openai:gpt-5-mini", api_key="...", api_base="https://example.test/v1"
) as model:
    agent = Agent(model=model)
    async with agent.run("Hello", tape="example", options={"max_tokens": 4096}) as stream:
        async for event in stream:
            print(event.kind, event.data)
```

`options` 是传递给每次模型调用的 Republic chat options，例如 `max_tokens`。Agent 会补入当前 Step 的工具。核心 SDK 不读取 `BUB_*` 配置；模型凭据通过 Republic 参数或其环境变量提供。

需要自定义回退、凭据选择或超时策略时，实现 `bub.core.ModelClient`：

| 成员 | 契约 |
| --- | --- |
| `spec` | 默认 `provider:model` 字符串，只读属性 |
| `max_tokens` | 默认输出 token 上限，或 `None` |
| `open_stream(messages, *, spec, options)` | 异步上下文管理器，产出 `(provider_name, republic_stream)` |

`messages` 是 `republic.Message` 列表，`options` 包含本 Step 的工具。`LLMCallStarted` 可以改写 `request.model`：使用 Republic chat model 时，同一提供商内复用客户端；跨提供商时根据 Republic 环境配置创建客户端。其他策略由自定义 `ModelClient` 实现。

## 传入文本与媒体 {#multimodal-input}

`prompt` 是内容列表，可以混合字符串和 Republic 的图片、音频、视频对象：

```python
async with agent.run(
    [
        "Describe the main problem shown in this screenshot.",
        republic.image("https://example.com/error.png", media_type="image/png"),
    ],
    model=model,
    tape="ui-review",
) as stream:
    ...
```

本地文件可以读取为 bytes，并显式指定 MIME 类型：

```python
from pathlib import Path

image = republic.image("image/png", data=Path("error.png").read_bytes())
```

音频和视频分别使用 `republic.audio()`、`republic.video()`。Bub 负责把媒体交给模型并保存可序列化的消息结构，不会替你转码或压缩；实际支持的格式、大小和模态取决于模型提供商。Tape 对媒体的记录边界见[Tape 与媒体](/zh-cn/docs/concepts/tape/#media)。

## 组合系统提示词 {#system-prompt}

`system_prompt` 接收文本、函数或两者的有序集合。函数接收 `PromptContext`，可以同步或异步返回字符串；Agent 在每个模型 Step 前渲染片段，忽略空结果并用空行拼接。

```python
from bub.core import PromptContext


@agent.system_prompt.add
def customer(context: PromptContext) -> str | None:
    if (name := context.state.get("user")) is not None:
        return f"You are helping {name}."
    return None
```

`PromptContext` 提供：

| 字段 | 内容 |
| --- | --- |
| `prompt` | 当前 Step 的新用户内容；延续对话时为空列表 |
| `tools` | 当前 Step 提供给模型的工具 |
| `available_tools` | Agent 注册的全部工具，未按 Step 筛选 |
| `model` | 当前模型标识 |
| `tape` | 当前运行的 Tape |
| `state` | 本轮共享状态，即 `tape.context.state` |
| `agent` | 当前 Agent |

`agent.system_prompt.remove(section)` 移除片段。传入的 `state` 不会自动持久化，跨运行恢复方式见[Tape 与状态](/zh-cn/docs/concepts/tape/#state)。

## 区分 Bub 工具与提供商工具 {#provider-tools}

传给 `Agent(tools=[...])` 的对象有两类：

```python
from republic.tools import WebSearch

agent = Agent(tools=[add_tool, WebSearch()])
```

- `add_tool` 是 Bub `Tool`，由 Bub 在宿主进程执行，经过事件、渲染和并发控制，保存在 `agent.tools`。
- `WebSearch()` 是 Republic 提供商工具，随请求交给模型提供商执行，保存在 `agent.builtin_tools`。

提供商工具不经过 Bub 的 `ToolExecutor`，因此不适用 Bub 的工具拦截、延迟加载或 code mode 分组。可用工具和行为以 Republic 及提供商支持为准。

## 构造参数 {#agent-options}

下表列出常用参数；完整参数、默认值和类型契约见 [Python API](/zh-cn/docs/reference/python-api/#agent)。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `model` | `None` | Republic chat model 或 `ModelClient` |
| `store` | 新的 `InMemoryTapeStore` | 同步或异步 Tape 存储 |
| `tools` | `()` | Bub 工具与提供商执行的工具 |
| `system_prompt` | `()` | 每个 Step 渲染的文本或函数片段 |
| `context` | `default_tape_context()` | Tape 条目到模型消息的选择策略 |
| `command_prefix` | `None` | 文本命令前缀；设置后可直接调用工具 |

`agent.tools` 按名称保存 `Tool`，`agent.builtin_tools` 保存提供商工具。不同 Run 之间的并发不受 `max_tool_concurrency` 控制，需要宿主协调。

## 高级运行控制 {#advanced-run-control}

以下入口用于需要自行控制 Agent 循环的场景；常规运行只需使用前面的构造参数和 `agent.run()`。

### 按步骤选择工具 {#customize-how-a-step-is-prepared}

需要按业务规则筛选工具时，继承 `Agent` 并覆写 `prepare_tools(tape, prompt)`。默认实现提供传入的工具，只排除 `exposure="command"`；`tape.context.state` 是本轮状态。

### 添加运行中的消息 {#pending-messages}

引导（Steering）把新消息加入当前 Run，排队（Queue up）则把消息留给后续 Turn。`MessagesPending` 和 `StepFinished` 提供前一种入口；应用的 `follow_up` 准入决策负责后一种。CLI 的操作方式见[在运行时引导 Agent](/zh-cn/docs/app/terminal/#steering)。

| 事件 | 触发时机 | 用法 |
| --- | --- | --- |
| `MessagesPending` | Step 构建请求时；尚未到达最后一个允许 Step 且无工具调用时 | 向 `event.messages` 追加用户内容；步骤结束时有新消息会继续 Run |
| `StepFinished` | Step 结束 | `status == "continue"` 时设置 `next_prompt`；`None` 表示直接延续对话 |

```python
from bub.core.events import MessagesPending, StepFinished

inbox: dict[str, list[str]] = {}


@agent.events.on(MessagesPending)
def send_queued(event: MessagesPending) -> None:
    event.messages.extend([text] for text in inbox.pop(event.tape.name, []))


@agent.events.on(StepFinished)
def check_results(event: StepFinished) -> None:
    if event.status == "continue":
        event.next_prompt = ["Check the tool results before answering."]
```

最后一个允许的 Step 后不会再次发出 `MessagesPending`；仍需继续时，运行以 `max_steps_reached` 错误结束。

### 自行管理 Tape 和步骤 {#manual-runs}

`agent.session(name, state=...)` 打开由调用方管理生命周期的 Tape 分支。将返回的 `Tape` 对象传给 `run_on()` 或 `run_once()`：

- `await agent.run_on(tape, prompt, model=...)` 启动完整模型循环并返回流，调用方必须关闭。
- `agent.run_once(prompt, model=..., tape=tape)` 只产出一个模型 Step，适合自行实现循环。

两者接收的是 `Tape` 对象，不是 Tape 名称。
