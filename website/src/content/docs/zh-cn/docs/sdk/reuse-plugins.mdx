---
title: 复用应用插件
description: 在现有 Python 服务中复用 Bub 插件的工具、hooks 和应用组件。
---

复用插件前先确定需要哪部分能力。直接导入工具最简单；`AgentPlugins` 接入 Agent 循环相关 hooks；`BubAgent` 提供应用默认行为；完整消息处理流程使用 `BubFramework.process_inbound()`。

| 需要 | 入口 |
| --- | --- |
| 只复用工具实现 | 导入公开组件，传给 `core.Agent`；见本文[复用搜索工具](#add-a-search-tool) |
| 复用拦截、系统提示或引导（Steering） | `AgentPlugins.attach()`；见本文[接入 Agent 循环 hooks](#extend-the-run) |
| 使用应用默认配置、技能和工具策略 | `framework.running()` + `BubAgent`；见本文[复用 BubAgent](#reuse-bubagent) |
| 执行完整消息 Turn | `process_inbound()`；见[嵌入应用](/zh-cn/docs/app/distribution/#embed-the-application) |
| 发布自有 CLI 或 wheel | 见[嵌入与分发](/zh-cn/docs/app/distribution/#publish-a-command) |

插件可能依赖其他 hooks、工具、状态字段或后台服务。接入前应查看插件文档，不能只复制其中一个函数。

## 复用搜索工具 {#add-a-search-tool}

[`bub-web-search`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-web-search) 提供 `web.search` 和 `web.read` 工具。将它安装到运行服务的 Python 环境：

```bash
uv add "bub[app]" \
  "bub-web-search @ git+https://github.com/bubbuild/bub-contrib.git@main#subdirectory=packages/bub-web-search"
```

插件使用应用配置代码，因此需要安装 `app` 可选依赖；宿主仍可使用 `core.Agent`，并保留自己的模型、Tape 名称和运行生命周期。

本例使用 Jina 搜索，启动前设置：

```bash
export BUB_SEARCH_PROVIDER=jina
export BUB_SEARCH_JINA_API_KEY=jina_...
export REPUBLIC_OPENAI_API_KEY=sk-...
```

保存为 `search_agent.py`：

```python
import asyncio
from pathlib import Path

import republic
from bub_web_search.tools import build_tools

from bub.core import Agent
from bub.core.store import FileTapeStore


async def main() -> None:
    tools = build_tools()
    if "web.search" not in tools:
        raise RuntimeError("Configure a search provider with BUB_SEARCH_* first.")

    agent = Agent(
        store=FileTapeStore(Path("sessions")),
        tools=[tools["web.search"]],
        system_prompt="Search for sources before answering. Include their URLs.",
    )
    async with republic.get_model("openai:gpt-5-mini") as model:
        async with agent.run(
            "Find the official Python asyncio documentation.",
            model=model,
            tape="research-42",
            options={"max_tokens": 4096},
        ) as stream:
            async for event in stream:
                if event.kind == "text":
                    print(event.data.get("delta", ""), end="", flush=True)
                elif event.kind == "error":
                    raise RuntimeError(str(event.data.get("message", "Agent failed")))
        print()


if __name__ == "__main__":
    asyncio.run(main())
```

运行：

```bash
uv run python search_agent.py
```

`build_tools()` 根据进程中的 Bub 配置构建当前已启用的工具。示例只把 `web.search` 交给 Agent；需要网页读取时，再加入返回字典中的 `web.read`。已有 Agent 可以在启动时通过 `agent.tools[search.name] = search` 添加工具。

## 接入 Agent 循环 hooks {#extend-the-run}

`AgentPlugins` 把插件 hooks 接到核心 Agent 的事件、提示词和工具上。

### 模型与工具调用 {#model-and-tool-calls}

[`bub-context-budget`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-context-budget) 估算模型输入的 token 数。超过阈值时，它添加一条系统指令，要求模型先调用 `tape.handoff`。

安装插件：

```bash
uv add "bub-context-budget @ git+https://github.com/bubbuild/bub-contrib.git@main#subdirectory=packages/bub-context-budget"
```

创建 Agent 后、首次运行前接入：

```python
from pathlib import Path

from bub_context_budget import plugin as context_budget

from bub import BubFramework
from bub.builtin.tools import tape_handoff
from bub.core import Agent
from bub.hooks.agent import AgentPlugins


def add_context_budget(agent: Agent) -> None:
    framework = BubFramework(config_file=Path("bub.yml"))
    AgentPlugins(framework, plugins=[context_budget]).attach(agent)
    agent.tools[tape_handoff.name] = tape_handoff
```

插件只修改请求和记录用量，不会自行执行 handoff，因此必须同时提供 `tape.handoff`。通过 `BUB_CONTEXT_BUDGET_MAX_CONTEXT_TOKENS` 或 `bub.yml` 中的 `context-budget.max_context_tokens` 设置上限；阈值预留 16,384 tokens。预算指令是否执行取决于模型。

Handoff 工具将模型提供的摘要存到 anchor 的 `state`。该摘要不会自动进入下一次请求，需要通过[上下文选择](/zh-cn/docs/concepts/tape/#context)或下一条提示词显式提供。

在服务启动时完成注册和 `attach()`。同一 Agent 的会话共用这些 hooks；需要不同插件集合时，分别创建 Framework 和 Agent。应用配置仍是进程级共享。

### 其他 Agent hooks {#other-hooks}

| Hook | 接入位置 |
| --- | --- |
| `before_llm_call` / `after_llm_call` | 对应模型调用事件，由 `attach(agent)` 接入 |
| `before_tool_call` / `after_tool_call` | 对应工具调用事件，由 `attach(agent)` 接入 |
| `continue_prompt` | `status == "continue"` 的 `StepFinished`；返回文本成为下一 Step 的用户消息 |
| `provide_steering_inbox` | `MessagesPending` 取出消息；步骤结束时有消息会继续 Run |
| `system_prompt` | `attach()` 在已有片段之后追加提示词 |
| `provide_tools` | `attach()` 添加工具；Agent 已有同名工具时保留原工具 |
| `provide_tape_store`、`build_tape_context`、`provide_tape_sidecar` | `plugins.components()` 提供 `store`、`context`、`sidecars` |
| `load_state`、`provide_environment` | `await plugins.build_state(...)` 准备运行状态 |

完整接入形式：

```python
from bub.hooks.agent import AgentPlugins

plugins = AgentPlugins(plugins=[SupportPlugin()])

async with plugins.running():
    agent = plugins.attach(Agent(system_prompt="Answer in plain text.", **plugins.components()))
    state = await plugins.build_state("customer-42", agent=agent)
    async with agent.run(prompt, model=model, tape="customer-42", state=state) as stream:
        ...
```

`components()` 只包含 hooks 实际提供的组件；显式传入的构造参数优先。存储和引导收件箱（`SteeringInbox`）只在 `plugins.running()` 内可用。先调用 `attach()`，再注册自己的事件处理器，后者才能看到 hooks 的修改。

`plugins=[...]` 只注册指定插件；不带参数的 `AgentPlugins()` 加载内置 hooks 和已安装插件。传入已有 `framework` 时使用它的 hooks，额外插件也注册到该 Framework。

`build_prompt`、`run_model`、`save_state`、`render_outbound`、`dispatch_outbound` 属于消息流程，只在 `process_inbound()` 中执行，不会由 `attach()` 接入核心 Agent。

### 后台服务 {#background-services}

MCP 等需要常驻连接的插件还有自己的生命周期，不能只用 `attach()` 代替启动和关闭。

按 [`bub-mcp` 的嵌入说明](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-mcp#embedding)，用 `MCPChannel.connect()` 建立连接，通过 `bind_agent()` 绑定工具，结束时调用 `stop()`。这段生命周期由宿主管理，与 `framework.running()` 分开处理。

## 复用 BubAgent {#reuse-bubagent}

`BubAgent` 已组合应用配置、技能、工具策略、Tape 组件和插件 hooks。需要这些默认行为但仍自行处理输出时，使用它的流入口：

```python
framework.load_hooks()

async with framework.running():
    agent = BubAgent(framework)
    stream = await agent.run_stream(session_id="customer-42", prompt=["Hello"])
    async with stream:
        async for event in stream:
            ...
```

在 `framework.running()` 内创建 Agent，才能取得该作用域提供的存储。`run_stream()` 只在 `state=None` 时通过 hooks 加载状态；需要请求元数据时，用 `framework.build_state(message, session_id)` 准备状态，并在消息中设置 `_runtime_agent`，再传给 `run_stream(state=...)`。

直接流入口会跳过初始 `build_prompt`、`save_state`、回复渲染和分发，也不协调同会话并发。需要完整 Turn 时使用 `process_inbound()`；它即使启用流式输出，也会自行消费流并返回完整 `TurnResult`。

内置系统提示词可能要求通过渠道回复。直接返回模型文本的服务应核对自己的提示词策略；替换 `agent.system_prompt` 会同时替换插件、技能、延迟工具和 code mode 的片段。
