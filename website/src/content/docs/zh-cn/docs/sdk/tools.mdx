---

工具让 Agent 查询数据、修改文件或调用外部服务。`Tool` 描述动作名称、参数和结果，可以直接传给 `Agent`，也可以在 [Bub 应用](/zh-cn/docs/app/tools/)中通过插件注册。

## 定义工具 {#define-the-action}

`Tool.from_callable()` 从类型标注生成参数 schema，从 docstring 读取描述，支持同步和异步函数：

```python
from bub.core import Agent
from bub.core.tools import Tool


def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b


add_tool = Tool.from_callable(add, name="math.add")
agent = Agent(tools=[add_tool])
```

运行时使用名称 `math.add`，提供给模型时将点替换为下划线，因此模型看到 `math_add`。可通过 `name=` 和 `description=` 显式覆盖名称与描述。

普通 `Agent` 向模型提供传入的工具，只排除 `exposure="command"`。延迟加载、`allowed_tools` 和 `state["code_mode"]` 是 [BubAgent 的策略](/zh-cn/docs/sdk/reuse-app/#run-stream-options)。核心 Agent 需要按 Step 选择工具时，覆写 [`prepare_tools()`](/zh-cn/docs/sdk/options/#customize-how-a-step-is-prepared)。

### 使用 Pydantic 参数模型 {#pydantic-input}

参数较多或需要约束时，用 `model=` 传入 Pydantic model。处理函数接收一个模型实例，而不是展开的字段：

```python
from pydantic import BaseModel, Field

from bub import tool


class RefundInput(BaseModel):
    order_id: str = Field(description="The order to refund")
    amount: float = Field(gt=0, description="Refund amount in the order currency")


@tool(name="orders.refund", model=RefundInput)
def refund_order(param: RefundInput) -> dict[str, str | float]:
    """Refund a paid order."""
    return {"order_id": param.order_id, "amount": param.amount}
```

字段描述和 JSON schema 会提供给模型。参数验证失败时，Bub 返回 `invalid_input` 工具错误，不会执行处理函数。需要 `ToolContext` 时，再加上 `context=True`，并把处理函数声明为 `(param, *, context)`。

## 返回模型可用的结果 {#return-data-the-caller-can-use}

工具可以返回字典、列表、Pydantic model 或字符串。`renderer` 将结构化结果转换为直接提供给模型的文本：

```python
from typing import TypedDict


class Order(TypedDict):
    id: str
    status: str


def lookup_order(order_id: str) -> Order:
    """Look up an order by id."""
    return {"id": order_id, "status": "shipped"}


order_tool = Tool.from_callable(
    lookup_order,
    renderer=lambda order: f"Order {order['id']}: {order['status']}",
)
```

`Tool.render(result)` 使用这个 renderer。默认渲染规则是：字符串原样保留，Pydantic model 和可序列化值转为 JSON，其他值使用 `str()`。

模型直接调用工具时，执行器在 `ToolCallFinished` 之前渲染成功结果，因此事件处理器看到的是模型将收到的内容。code mode 使用 `render=False`，保留结构化结果。

模型循环中的工具错误会作为工具结果交回模型；直接命令调用的错误则传播给调用方。事件处理器自身的异常规则见[事件分发](/zh-cn/docs/concepts/events/#handlers)。

### 返回图片、音频或视频 {#media-results}

普通 renderer 只产生文本。需要让模型读取媒体时，用 `content_result()` 同时返回文本和媒体：

```python
from pathlib import Path

import republic

from bub.core.tools import Tool, content_result


def read_chart(path: str) -> dict:
    """Read a chart image for the model."""
    return content_result([
        "The chart generated by the latest test run:",
        republic.image("image/png", data=Path(path).read_bytes()),
    ])


chart_tool = Tool.from_callable(read_chart)
```

`content_result()` 把内容转换为可写入 Tape 的 JSON 结构。直接工具调用会把其中的文本和媒体交给模型；code mode 则保留结构化结果，供生成代码继续处理。需要只取回模型内容时，可以使用对应的 `result_content()`。

## 访问当前会话 {#use-the-current-conversation}

设置 `context=True` 后，工具通过关键字参数 `context` 接收 `ToolContext`：

```python
from bub.core.tools import ToolContext


async def remember(note: str, *, context: ToolContext) -> str:
    """Record a note for this conversation."""
    await context.tape.append_event("note", {"text": note})
    return "Recorded."


remember_tool = Tool.from_callable(remember, context=True)
```

`ToolContext` 提供当前 `tape`、共享 `state`、`run_id` 和 `events`，以及 `code_mode`、`command` 标记。

`append_event()` 写入的是业务 `event` 条目。默认上下文选择器会跳过它；需要让模型读取该事件时，提供自定义[Tape 上下文](/zh-cn/docs/concepts/tape/#context)。

## 通过文本命令调用工具 {#call-a-tool-without-a-model}

设置 `command_prefix` 后，可以不经模型直接调用工具：

```python
import asyncio


async def calculate() -> None:
    agent = Agent(tools=[add_tool], command_prefix=",")
    async with agent.run(",math.add a=2 b=3", tape="calculator") as stream:
        async for event in stream:
            if event.kind == "text":
                print(event.data["delta"])


asyncio.run(calculate())
```

该示例输出 `5`。命令使用 `math.add` 这个运行时名称，发出工具事件和 `CommandFinished`，不进入模型 Run。

参数先按工具参数顺序接收位置值，再解析 `key=value`。前缀不能为空或包含空白。命令名未注册时，如果 Agent 提供 `bash` 工具，整行会交给它执行；应用中的 shell 命令应视为可信代码。

[Bub 应用](/zh-cn/docs/app/tools/)还提供 `,skill`、`,code_mode` 等命令。

## 组合工具与 code mode {#compose-tools-with-codemode}

code mode 让模型编写 Python，在一次 `run_code` 调用中组合多个工具。`CodeMode` 提供 `run_code` 工具和描述可用工具的提示词片段；核心 Agent 需要显式加入这两部分：

```python
from bub.core.codemode import CodeMode

code_mode = CodeMode([add_tool, order_tool])
agent = Agent(
    tools=[code_mode.run_code],
    system_prompt=[
        "Use the available tools to answer the user's question.",
        code_mode.prompt,
    ],
)
```

模型可以向 `run_code` 提交：

```python
order = await tools.lookup_order(order_id="A123")
print(order["status"])
```

代码中的工具名使用下划线，参数使用关键字，支持顶层 `await`。结果保留结构化形式，`run_code` 只返回代码打印的内容，因此需要显式 `print()`。工具调用仍经过 `ToolCallStarted` 和 `ToolCallFinished`，此时 `context.code_mode=True`。

代码还可以把生成的图片、音频或视频附加到结果中，让模型继续读取：

```python
await tools.attach_image(image="artifacts/chart.png")
print("Chart attached.")
```

`attach_image`、`attach_audio`、`attach_video` 接受环境中的文件路径、URL、data URL 或对应 Republic 媒体对象。它们只在 `run_code` 内有效。

`CodeMode` 只使用你传入的工具，并排除 `exposure="command"`。BubAgent 对 `auto`、`direct`、`code` 工具的分组规则见[应用工具](/zh-cn/docs/app/tools/#code-mode)。

### CodeMode 参数 {#codemode-options}

| 参数 | 默认值与行为 |
| --- | --- |
| `tools` | `()`。固定工具集合，或根据本轮状态返回集合的函数；返回 `None` 时禁用本轮 code mode |
| `environment` | `LocalEnvironment()`。也可传入根据状态选择环境的函数 |
| `models` | `None`。Republic 默认模型标识或解析函数；未设置时，代码必须显式给出模型标识 |
| `stub_dir` | `None`，工具定义直接进入系统提示词；指定目录时写入 `.pyi` 文件，Agent 需要能读取它 |
| `media_tools` | `True`，提供 `attach_image`、`attach_audio`、`attach_video` |
| `name` | `"run_code"` |

代码可以通过 Republic 桥接接口调用聊天、嵌入和决策模型。调用由宿主进程解析，模型凭据不需要传给生成的代码。

`run_code(code, timeout_seconds=120)` 返回打印输出和附加媒体。默认本地环境会启动拥有宿主用户权限的 Python 进程，并在完成或取消时停止进程树；它不是安全沙箱。需要隔离执行时，提供其他 `Environment`。

### 在代码中调用模型 {#republic-models}

`run_code` 中的 `republic` 不只是媒体构造模块，还能调用聊天、嵌入和决策模型。代码拿到的是代理对象，真正的请求由宿主进程发出；模型凭据不会传给生成的代码。

`CodeMode(models=...)` 决定模型标识如何解析。传字符串时，它是不带参数调用 `republic.get_model()` 的默认模型；传解析函数时，可以按本次 `ToolContext` 选择模型和客户端参数。应用中的 `BubAgent` 已接入当前会话模型、凭据和 API 地址。

等待完整聊天响应：

```python
model = republic.get_model()
response = await model.chat("Explain why the last tool call failed.", max_tokens=300)
print(response.text)
```

也可以传入消息列表，混合 `republic.system()`、`republic.user()`、`republic.assistant()` 和媒体对象。这里的模型调用**不能携带工具**；需要执行动作时，仍使用 `tools.*`。

需要逐块处理输出时，使用流：

```python
from republic.events import TextDelta

model = republic.get_model("openai:gpt-5-mini")
async with model.stream("Summarize the current task.") as stream:
    async for event in stream:
        if isinstance(event, TextDelta):
            print(event.chunk, end="")

print("\nFull response:", stream.text)
```

流只能迭代一次，且必须完整消费后才能读取 `stream.response`、`stream.text` 和 `stream.token_usage`。`async with` 会关闭流；代码提前结束时，`CodeMode` 也会清理尚未关闭的流。

嵌入模型使用 `embed()` 或 `embed_many()`：

```python
model = republic.get_embedding_model("openai:text-embedding-3-small")
response = await model.embed_many(["first document", "second document"])
print(len(response.vectors), len(response.vectors[0]))
```

决策模型一次回答一组问题，支持 `Noul`、`Choice` 和 `Score`：

```python
from republic.decisions import Choice, Noul

model = republic.get_decision_model("openai:gpt-5-mini")
response = await model.decide(
    {"tests_passed": False, "reviewed": True},
    questions={
        "ready": Noul("Can this change be released?"),
        "next_action": Choice("What should happen next?", ["fix", "review", "release"]),
    },
)
print(response.answers)
```

这些调用和普通模型请求一样可能失败或超时，并受 `run_code` 的整体超时约束。需要限制生成代码可使用的模型时，应实现自定义 `ModelResolver`，不要只依赖提示词约束。

## 选择执行环境 {#choose-an-execution-environment}

`bub.environment.Environment` 定义进程执行、文件访问和 Python 执行接口：

| 成员 | 契约 |
| --- | --- |
| `spawn(command, *, cwd=None, env=None)` | 返回 `Process`，提供输出流、输入、等待和进程树信号控制 |
| `read_text(path)` / `read_bytes(path)` | 读取环境内的文件 |
| `write_text(path, content)` | 写入 UTF-8 文本并创建父目录 |
| `workspace` / `resolve_path(path)` | 定义工作目录并解析相对路径 |
| `run_code(code, *, tools, call_tool, write)` | 执行支持顶层 `await` 的 Python；通过 `call_tool` 调工具，通过 `write` 输出 stdout |
| `close()` | 释放环境持有的资源 |

`CodeMode(environment=...)` 使用指定环境。应用中通过 [`provide_environment`](/zh-cn/docs/reference/hooks/) 为会话提供环境，Framework 在 `running()` 退出时关闭它；核心 SDK 中由调用方负责关闭。
