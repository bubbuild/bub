工具让模型能够查询事实或执行动作。`@tool` 把带类型标注的 Python 函数转换成 `Tool`：函数名、类型注解和 docstring 共同构成模型可见的调用契约。

本章给订单助手增加 `get_order`，重点不只是“让工具跑起来”，而是明确模型看到什么、错误如何返回，以及副作用由谁负责。

## 查询订单的完整示例 {#complete-example}

将 `main.py` 改为：

```python
import asyncio

import republic

from bub.core import Agent
from bub.core.tools import tool


ORDERS = {
    "A123": {
        "order_id": "A123",
        "status": "shipped",
        "item": "机械键盘",
        "amount": 399.0,
    }
}


@tool
async def get_order(order_id: str) -> dict[str, str | float]:
    """按订单号查询订单状态、商品和金额。订单不存在时返回 error。"""
    await asyncio.sleep(0.1)  # 模拟非阻塞数据库查询
    if order := ORDERS.get(order_id):
        return order
    return {"order_id": order_id, "error": "order_not_found"}


async def main() -> None:
    agent = Agent(
        tools=[get_order],
        system_prompt="你是订单客服助手。查询订单必须使用工具，不要猜测订单状态。",
        max_steps=6,
        max_tool_concurrency=2,
    )

    async with republic.get_model("openai:gpt-5-mini") as model:
        async with agent.run(
            "帮我查一下订单 A123 现在是什么状态。",
            model=model,
            tape="customer-42",
        ) as stream:
            async for event in stream:
                if event.kind == "tool_call":
                    for call in event.data["tool_calls"]:
                        print(f"\n[请求工具] {call['name']} {call['arguments']}")
                elif event.kind == "tool_result":
                    print(f"[工具结果] {event.data['tool_results']}")
                elif event.kind == "text":
                    print(event.data["delta"], end="", flush=True)
        print()


if __name__ == "__main__":
    asyncio.run(main())
```

沿用上一章设置的 `REPUBLIC_OPENAI_API_KEY`，运行：

```bash
uv run python main.py
```

一次典型运行包含两个 Step：

1. 模型请求 `get_order(order_id="A123")`，Bub 执行函数并产生 `tool_result`。
2. 下一 Step 把订单结果交给模型，模型根据真实结果生成回答。

模型是否调用工具仍由模型决定。系统提示可以引导行为，但订单状态必须来自工具结果，不能把提示词当作数据正确性的保证。

## 设计模型能理解的参数契约 {#schemas}

### 类型与描述属于模型接口

参数类型会进入 JSON Schema，docstring 会进入工具描述。应写出业务含义和约束，而不只是重复参数名：

```python
@tool
async def get_order(order_id: str) -> dict[str, str | float]:
    """按订单号查询订单。order_id 是用户提供的完整编号，例如 A123。"""
    ...
```

参数较多或需要额外校验时，使用 Pydantic 模型：

```python
from pydantic import BaseModel, Field

from bub.core.tools import tool


class RefundInput(BaseModel):
    order_id: str = Field(description="完整订单编号，例如 A123")
    amount: float = Field(gt=0, description="退款金额，必须大于 0")
    reason: str = Field(min_length=1, description="用户提供的退款原因")


@tool(name="refund_order", model=RefundInput)
def refund_order(param: RefundInput) -> dict[str, str | float]:
    """为已支付订单申请退款；执行前必须完成权限检查。"""
    return {
        "order_id": param.order_id,
        "amount": param.amount,
        "status": "refund_requested",
    }
```

参数校验失败会转换成工具错误并进入 `tool_result`，模型可以据此修正参数后重试，但不保证一定重试成功。领域状态（例如“订单不存在”）可以返回稳定的结构化错误，便于模型和调用方区分。

## 返回值、异常与副作用 {#results-and-errors}

普通返回值会经 `Tool.render()` 转换成模型文本：字符串保持原样，Pydantic 模型和字典等结构化值默认序列化为 JSON。需要控制模型看到的格式时传入 `renderer`；不要把只供宿主使用的密钥或内部字段放进返回结果。

| 情况 | 默认行为 |
| --- | --- |
| 参数不符合类型或 Pydantic 约束 | 转为参数校验工具错误，交回模型 |
| 工具抛出普通异常 | 转为工具错误，交回模型 |
| 工具返回业务错误对象 | 作为正常工具结果交回模型 |
| 存储、模型或事件处理器中断 Run | 异常可能从事件迭代抛出，由宿主处理 |

**工具副作用不是 Tape 事务的一部分。** 已退款、已发送邮件或已修改的文件，不会因后续模型调用失败、客户端取消或 `merge_back=False` 而回滚。写操作应具备权限校验、幂等键和必要的业务补偿；不要只依赖模型“不要重复调用”的提示。

### 返回图片等媒体 {#media-results}

需要把媒体交给当前模型调用时，使用 `content_result()`，而不是把二进制数据塞进 JSON：

```python
import republic

from bub.core.tools import content_result, tool


@tool
def get_invoice_preview(invoice_id: str) -> dict[str, object]:
    """返回发票说明与预览图。"""
    return content_result([
        f"发票 {invoice_id} 的预览",
        republic.Image("image/png", url="https://example.test/invoice.png"),
    ])
```

媒体结果用于当前模型输入，不等于媒体持久化方案。需要审计或重放时，由宿主保存文件并在业务记录中保存可解析的引用。

## 注入本次 Run 的上下文 {#tool-context}

工具需要会话名、请求级权限或事件总线时，使用 `ToolContext`。它由 Bub 注入，不会出现在模型可见的参数 Schema 中：

```python
from bub.core.tools import ToolContext, tool


@tool(context=True)
async def add_order_note(note: str, *, context: ToolContext) -> str:
    """向当前会话追加一条订单备注。"""
    await context.tape.append_event(
        "order.note",
        {"text": note, "request_id": context.state.get("request_id")},
    )
    return f"备注已写入会话 {context.tape.name}"
```

运行时传入本次状态：

```python
async with agent.run(
    prompt,
    model=model,
    tape="customer-42",
    state={"session_id": "customer-42", "request_id": "req-01"},
) as stream:
    ...
```

`context.state` 只在当前 Run 内共享，不会自动恢复。`append_event()` 会追加历史记录，但普通业务事件默认不会成为下一次模型输入；需要模型看到它时，还应设计相应的上下文投影。

## 同步函数、异步函数与并发 {#concurrency}

模型在一次响应中可以请求多个工具。`Agent(max_tool_concurrency=...)` 限制**这一批工具调用**的并发数：`None` 不限制，`1` 按顺序执行。它不是整个应用的全局限流器。

同步工具函数会直接在当前事件循环中调用。数据库驱动、文件处理或第三方客户端如果会阻塞，应放在线程中，避免卡住其他请求：

```python
@tool
async def export_order_report(order_id: str) -> str:
    """生成订单报表并返回下载地址。"""
    return await asyncio.to_thread(build_report_blocking, order_id)
```

`async def` 并不自动让阻塞代码变成非阻塞代码；只有真正的异步 I/O 或显式卸载到线程才有用。

传给 `Agent(tools=[...])` 的还可以是 `republic.tools.WebSearch()` 等提供商工具。它们由模型提供商执行，不经过本地 `ToolExecutor`，也不受 `max_tool_concurrency` 的本地并发限制。

## 不经过模型，直接调用工具 {#call-a-tool-without-a-model}

需要确定性的命令入口时，可以给 Agent 设置 `command_prefix`。命令仍使用同一个工具实现和参数校验，但不调用模型：

```python
agent = Agent(tools=[get_order], command_prefix=",")

async with agent.run(",get_order A123", model=model, tape="customer-42") as stream:
    async for event in stream:
        if event.kind == "text":
            print(event.data["delta"], end="")
```

直接命令产生 `CommandFinished` 和文本结果，不产生 `RunStarted` / `RunFinished`。命令错误直接交给调用方处理，不会像模型工具错误那样交给模型自行修正；需要覆盖命令路径的权限策略仍应放在 `ToolCallStarted`。

## 进阶：用 Code Mode 组合工具 {#compose-tools-with-codemode}

工具很多或需要一段条件逻辑时，可以让模型通过 `run_code` 编写 Python，在一次执行中组合多个工具：

```python
from bub.core.codemode import CodeMode

code_mode = CodeMode([get_order])

agent = Agent(
    tools=[code_mode.run_code],
    system_prompt=[
        "使用可用工具完成任务；可以编写 Python 调用 tools.*。",
        code_mode.prompt,
    ],
)
```

模型生成的代码可以调用：

```python
order = await tools.get_order(order_id="A123")
print(order)
```

### 选择执行环境 {#choose-an-execution-environment}

`Environment` 定义代码进程创建、文件读写、代码执行和关闭等契约。默认 `LocalEnvironment` 在宿主机启动 Python 进程；远程或隔离环境可以提供不同的文件系统、网络和权限边界。

:::caution
**独立进程不等于安全沙箱。** 不要把不可信模型代码的宿主执行误认为安全边界；需要隔离时配置具备文件系统、网络和权限限制的 `Environment`，完整协议见 [Python API](/zh-cn/docs/reference/python-api/)。
:::
