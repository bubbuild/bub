Bub 是一个用 Python 写的 agent 运行时。它要求 Python 3.12 或更高版本，用 `pip` 或 `uv` 从 PyPI 安装。

你给 Bub 三样东西：一个模型、一组工具、一个存放对话的地方。然后它重复同一个循环：调用模型，执行模型要求的工具，把结果写进对话，再调用模型。模型不再要求工具、直接给出回答时，循环结束。

Bub 其余的部分，都是为了让这个循环在演示之外也能用：配置、存储、渠道、插件，以及看清一次运行在做什么的手段。

## 它由什么组成

Bub 分两层。

**内核**（`bub.core`）有循环、工具接口、对话记录、事件总线和模型客户端。它用 `republic` 调用模型，依赖 `pydantic` 和 `loguru`。

**应用层**（`bub[app]`）加上让内核变成一个能直接运行的程序所需的部分：配置和配置文件、插件与 hooks、技能、消息渠道、网关，以及 `bub` 命令。

`pip install bub` 只装内核。`pip install "bub[app]"` 两层都装。

## 两种用法

| | 使用 Bub 应用 | 构建你的 Bub Agent |
| --- | --- | --- |
| 运行的是什么 | `bub` 命令，独占一个进程 | 你自己的 Python 程序 |
| 怎么启动 | `bub chat`、`bub run`、`bub gateway` | `Agent(...)` |
| 你需要提供 | 模型和渠道配置 | 模型、工具、一个 tape |
| Bub 提供 | 配置、插件、技能、hooks、渠道 | 循环和它的事件 |

想要一个在终端或聊天软件里就能用的 agent，用应用。想给自己跑的服务加上 agent 行为，就自己构建。

两者并不冲突。导入 `BubAgent` 的程序会拿到内核，外加应用的配置和插件 hooks，但不需要跑 `bub` 命令。

## 核心设计

几条约束让循环保持简单：

- 历史只追加。每一轮写进 tape。模型读的是这份记录的一个切片，而不是一个无限增长的 chat 数组。
- 每一步都发事件。模型调用和工具调用各自发出开始、结束和结果。宿主可以旁观一次运行，改掉下一次的输入，或者把它停下来。
- 工具就是函数。带类型标注的 Python 函数就够了。code mode 让模型写一小段程序，一步里调用多个工具。
