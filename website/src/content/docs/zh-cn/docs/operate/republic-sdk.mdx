Bub 的所有模型请求都使用 Republic。agent loop、ToolExecutor、hooks、模型选择与回退、流式 UI 和 tape
仍由 Bub 管理。本分支使用**尚未发布的本地 SDK 基准**，安装 PyPI 旧版 Republic 无法运行。

## 安装必需依赖

Bub 需要 Python 3.12+。请将两个 checkout 放在同一目录下：

```text
workspace/
  republic-dev/       # Republic dev，已验收的 SDK 重建代码
  bub-republic-dev/   # Bub feat/republic-provider-sdk
```

在 Bub 执行 `uv sync --locked --extra trace`，会从仓库相对路径 `../republic-dev` 安装必需依赖
`republic>=0.5.9.dev26,<0.6`。锁文件记录相对来源，不固化本机路径或无法获取的远端提交。
`trace` 仅为可选遥测功能。当前源码安装要求两个 checkout，已移除的旧 SDK 不会安装。

如需仅用 wheel 部署，分别构建两库 wheel，在同一次依赖解析中安装两个显式产物：

```bash
uv pip install --python /explicit/venv/bin/python \
  /explicit/path/to/bub-VERSION-py3-none-any.whl \
  /explicit/path/to/republic-VERSION-py3-none-any.whl
uv pip check --python /explicit/venv/bin/python
```

Bub wheel 声明正常 Republic 依赖，不携带本地 uv source。下方验收脚本会从导出的依赖中排除 sibling source，
构建 Bub 并安装指定 Republic wheel 及其依赖。这不代表未发布提交或 wheel 已可从远端安装。

## 协议配置

```yaml
model: openai:your-responses-model
api_key: YOUR_EXPLICIT_API_KEY
republic_protocols:
  openai: responses
max_tokens: 16384
completion_args:
  temperature: 0.2
```

协议环境配置为 `BUB_REPUBLIC_PROTOCOLS='{"openai":"responses"}'`。API key/base URL 继续支持
`BUB_API_KEY`、`BUB_API_BASE` 的标量或 provider 映射，以及 `BUB_OPENAI_API_KEY` 等字段。
`OPENAI_API_KEY`、`OPENROUTER_API_KEY`、`ANTHROPIC_API_KEY` 是较低优先级的默认值。
模型名只按第一个冒号拆分，例如 `openrouter:vendor/model:free` 保留完整模型 ID。

| 模型前缀 | 协议配置 | 默认路径 |
| --- | --- | --- |
| `openai:` | `chat`，默认 | OpenAI `/v1/chat/completions` |
| `openrouter:` | 仅 `chat` | `https://openrouter.ai/api/v1/chat/completions` |
| `openai:` | `responses` | OpenAI `/v1/responses` |
| `anthropic:` | `messages`，默认 | Anthropic `/v1/messages` |
| `openai:` | `codex`，或已有 Bub 登录且无 key/base/协议覆盖 | `https://chatgpt.com/backend-api/codex/responses` |

`api_base` 可覆盖 API-key 协议地址。不支持的 provider/protocol 明确报配置错误，没有其他 SDK 回退路径。
onboarding 提供 OpenRouter、OpenAI、OpenAI-compatible 自定义地址、Anthropic，使用官方 SDK 查询模型且禁用重试。
模型列表成功不证明工具能力或推理授权；Codex 跳过 API-key 模型发现。Bub 尚未接入 Copilot/Grok 登录 UX。

## ChatGPT/Codex 登录与现有凭据

`bub login openai` 保留浏览器和本地回调 UX；`--manual --no-browser` 接受完整回调 URL 或裸授权码。
URL 必须包含正确的 state，Republic 负责 PKCE 与标准 OAuth 交换，Bub 负责手动输入 UX。
新登录沿用 `CODEX_HOME/auth.json`（默认 `~/.codex/auth.json`）的嵌套 `tokens` 格式。
`--codex-home` 指定登录目录；使用自定义目录时，运行时 `codex_home` / `BUB_CODEX_HOME` 也应设为同一路径。
现有可解析的 auth.json 直接复用，读取不写盘、不搬家，无需迁移步骤。

自动选择 Codex 仅适用于未显式设置 base URL 或协议的 `openai:`。普通 API key 使用标准 API；
带 ChatGPT account claim 的显式 access token 可直接走 Codex，无需 refresh token 或已知 expiry。
没有显式 key/base 时，可解析的 auth.json 才会选择 Codex；不能只凭文件存在或模型名含 codex 判断。
显式协议映射仍决定协议，并允许显式凭据和 endpoint。

Bub 保留原到期策略：优先 `tokens.expires_at`（数字或 RFC3339），其次 access JWT `exp`，
再其次 `last_refresh + 3600`，均缺失时使用当前时间加 3600。这些 fallback 是 Bub 的时效估计，
不是服务端保证；JWT claim 只作未验证的路由和时效提示。Republic 不强制这些策略。
Bub 在推理前提前 120 秒刷新；刷新失败而旧 token 尚未到期时继续使用，已过期则失败。
刷新成功原地更新 auth.json 的 token、expiry、account 和 last_refresh，保留未知顶层/嵌套字段；
没有新 account 时沿用旧值。原子写使用 0600 权限，轮换后保存失败会阻止推理。
不在 401 后刷新重发，不在推理时弹登录 UI；跨进程刷新锁仍未提供。

Republic 提供认证和请求能力，接受已有凭据。Bub 默认工厂显式设 SDK 重试为零；
自定义工厂可选择自己的 transport 策略。ChatGPT token 不是通用 OpenAI API key。
本轮证据均为合成 fixtures，真实账号登录、推理、刷新和 entitlement 仍未验收；没有新增 Copilot/Grok 登录 UX。


## 请求选项与媒体

`completion_args` 使用 Republic `RequestOptions`：`temperature`、`top_p`、`stop`、`tool_choice`、
`parallel_tool_calls`，以及原生 `provider_options`。`max_tokens` 转成 `max_output_tokens`，重复设置报错。
未设置时 API-key 协议使用 16384；Codex 不发送该限制，显式设置会报错。model/messages/tools/stream 等字段不允许覆盖。
非空 `client_args` 明确拒绝。tape 的 `reasoning_effort` 映射到 Chat 或 Responses/Codex 原生选项；
`auto` 省略，冲突报错。Anthropic 默认 ephemeral `cache_control`，显式原生选项优先；thinking 通过 `provider_options` 配置。

`build_prompt` 的 image_url、input_audio、video_url 按原顺序转为 Republic FilePart。
Chat、Responses、Anthropic 和 Codex 接通图片；内联音频使用 Chat（OpenAI 原生 mp3/wav，兼容服务可支持更多格式）；
video_url 是 OpenRouter/兼容 Chat 扩展，不代表 OpenAI 原生视频能力。Anthropic、Responses、Codex 仍不支持音视频。
协议不支持的媒体组合和未知字段在 HTTP 前明确报错。SDK 不下载 URL 或读取本地文件；Bub 既有 channel media fetcher
仍在 build_prompt 前处理调用方提供的附件。生成图片/音频与独立语音/转写操作不属于本次消息输入路径。

Republic 另提供独立 OpenAI embeddings 与直接 Cohere v2 rerank，Bub 不新增检索或重排编排。
reasoning 使用既有 UI event，完整原生消息独立持久化。Codex 使用一次 SSE 请求，领先的 system 消息成为 instructions，
不经 Chat 中间转换，不重排历史。

## 生命周期、工具与回退

`ModelRunner.run` 直接使用 Republic Request/Response/events。每次尝试拥有并关闭自己的 adapter/client。
嵌入者可覆盖 async `ModelRunner.create_provider(candidate)`，返回以 `client=...` 构造的 adapter。
借用的官方 client 不被修改或关闭，保留调用者配置的重试策略，最终由调用者关闭 client。
Bub 在成功、失败、超时、取消和提前 `aclose()` 时关闭 stream；停止消费时调用者必须关闭 stream。

只有完成的 `stop`/`tool_call` 可继续。工具须保有原始 ID/名称、对象 JSON 参数及 completed 原生 item 状态（若有）。
截断、失败、未知终止原因、无效参数不执行工具；原生终止输出保存在 tape 的 `context=false` 记录中，不进入下次历史。
断流/取消不记录成功 chat。工具异常/拒绝经过 hooks 后保留：Anthropic 使用 `is_error`，Chat/Responses/Codex 使用
含 `is_error: true` 的显式 JSON 结果。Republic 不执行工具、不续轮；Bub agent loop 可在 `max_steps` 内继续。

`fallback_models` 是 Bub 策略，仅在尚无任何原生流事件的 ProviderError 时尝试下一候选。
已有输出、无效历史/选项、不完整终止均不回退。Bub 默认工厂显式禁用 SDK 重试，每个候选一次 HTTP；自定义工厂可选择自己的 transport 策略，Republic 不自动刷新。

## tape 兼容边界

消息增加 `_republic`，包含 `version: 1`、协议标签和完整 Republic Message JSON。工具调用记录增加 `message`，
工具结果记录增加 `messages`；可见 content/calls/results 保留。新进程从实际 JSONL 还原 Responses item ID、
encrypted reasoning、Anthropic signature 和原始 call ID。usage 原生/raw 字段、finish reason 随 run event 保存。

旧文本、image_url/input_audio/video_url 及完整 function 历史可读。tape 保留这些媒体的 URL/base64 字段和顺序；
原过滤路径仍过滤未知块类型或额外媒体字段。完整 FilePart 与 metadata 可通过原生 envelope 往返。
未知旧消息 metadata 和缺失工具身份明确报错。原生历史不能直接换协议，
应新建 tape 或显式迁移。hook 不能只改可见文本而留下旧原生数据。旧 Bub 版本不理解 envelope，无法保证无损续用。
tape 写入失败向外传播，不重跑已执行工具；外部副作用与持久化不构成事务，崩溃窗口不保证 exactly-once。

## 复现离线验收

```bash
python scripts/check_republic_wheel.py \
  /explicit/path/to/republic-VERSION-py3-none-any.whl \
  --source-commit 3c5638118952744cd53738be956d1c02354f5fc8
```

脚本新建 Python 3.12 环境（含 trace extra），安装两个 wheel，运行 `uv pip check`，断言旧 SDK 不存在、两库均从
site-packages 导入、安装文件与指定 wheel 一致，并记录版本/hash/source commit。不会依赖 editable sibling。

真实官方 SDK + HTTPX fixtures 验证 Chat/OpenRouter、Responses、Anthropic、Codex 的双进程链：
build_prompt 构造媒体消息，第一次模型请求工具，Bub 执行一次并落盘；第二进程读取 JSONL，按原顺序回传媒体、
原生 encrypted reasoning/signature（适用协议）和 call ID，得到结果。Chat 另覆盖内联音频和兼容视频回传。每进程一次 HTTP、资源释放、工具只执行一次。
另覆盖 agent loop、Chat/OpenRouter、Codex 授权/刷新、CLI/config、tracing、hooks/fallback、错误工具、截断、落盘失败及取消。

测试不需要真实凭据；模型 SDK 是运行和测试的必需依赖，不会因缺失而跳过。常规检查为 `make check/test/docs-test`。
这些证据不证明真实账号 entitlement、OAuth live 登录或在线推理已验收。

SHA256 `4053168afadc79e5f9e0e913eb173c2de11e96782f971d6dce6f51fed1d7ecdc`。
