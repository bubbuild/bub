Bub is a lightweight agent runtime written in Python. It ships a ready-to-run agent application, and it lets you replace the execution logic and compose plugins as you see fit.

An agent is at heart a loop: the model reads the context and decides which tool to call, the tool result goes back into the context, and the model reads it again. The loop ends when the model stops asking for tools and answers directly.

So an agent rests on four things: a **model**, **tools**, a **context**, and the **loop** that drives them. Working from that shared understanding, Bub keeps a small core and builds a ready-to-run application around it:

<CardGrid>
  <Card title="The core layer" icon="puzzle">
    Composable agent capabilities: the loop, tools, context, the event bus, and the model client.

    It calls models through [republic](https://getrepublic.org); the remaining core dependencies are [pydantic](https://pydantic.dev), [loguru](https://github.com/delgan/loguru), and typing-extensions.
  </Card>
  <Card title="The app layer" icon="rocket">
    A ready-to-run harness on top of the core: settings, plugins, hooks, skills, message channels, and a gateway.

    None of it needs to be built yourself; a little configuration is enough to start.
  </Card>
</CardGrid>

Which one should you use?

- If you want to **combine Bub with your existing codebase or service**, use the core layer [SDK](/docs/sdk/) directly;
- If you want **Bub to work out of the box**, use the app layer [App](/docs/app/workspace/).

<Aside type="tip">
  The two are not exclusive. When you need to, you can even [reuse the App inside the SDK](/docs/sdk/reuse-plugins/#reuse-bubagent).
</Aside>

## Core design {#core-design}

Bub is built on being simple, composable, and extensible. That means you can freely combine Bub's capabilities, or build your own agent on top of it:

<CardGrid>
  <Card title="Append-only context" icon="database">
    Each turn appends to the tape and never rewrites an entry. The model reads a slice of the tape, not a message array that keeps growing.
  </Card>
  <Card title="Event-driven" icon="analytics">
    Model calls and tool calls each emit a start, an end, and a result. A host can watch a run, rewrite the next input, or abort it outright.
  </Card>
  <Card title="Tools are functions" icon="code-branch">
    A type-annotated Python function is enough to become a tool. Code mode lets the model write a short program that calls several tools in one step.
  </Card>
  <Card title="Pluggable" icon="setting">
    Every capability in Bub can be provided by a plugin. A plugin can be a tool, an event listener, a message channel, or a whole set of skills.
  </Card>
</CardGrid>

The [concepts](/docs/concepts/) section defines all of this in full.
