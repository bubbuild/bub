Bub is an agent runtime written in Python. It needs Python 3.12 or newer and installs from PyPI with `pip` or `uv`.

You give Bub three things: a model, a set of tools, and a place to keep the conversation. Then it repeats one loop. It calls the model, runs the tools the model asks for, writes the results to the conversation, and calls the model again. The loop ends when the model answers without asking for a tool.

Everything else in Bub exists to make that loop usable outside a demo: settings, storage, channels, plugins, and a way to watch what a run is doing.

## What it contains

Bub has two layers.

**The kernel** (`bub.core`) has the loop, the tool interface, the conversation record, the event bus, and the model client. It uses `republic` for model calls, and depends on `pydantic` and `loguru`.

**The application layer** (`bub[app]`) adds what turns the kernel into a program you can run: settings and config files, plugins and hooks, skills, message channels, a gateway, and the `bub` command.

`pip install bub` installs the kernel. `pip install "bub[app]"` installs both layers.

## Two ways to use it

| | Use Bub App | Build your own Bub Agent |
| --- | --- | --- |
| What runs | the `bub` command, in its own process | your Python program |
| How you start it | `bub chat`, `bub run`, `bub gateway` | `Agent(...)` |
| What you provide | model and channel settings | a model, tools, and a tape |
| What Bub provides | settings, plugins, skills, hooks, channels | the loop and its events |

Use the app when you want an agent that already works in a terminal or a chat service. Build your own agent when you are adding agent behavior to a service you run yourself.

The two are not exclusive. A program that imports `BubAgent` gets the kernel plus the app's settings and plugin hooks, without running the `bub` command.

## Core design

A few rules keep the loop small:

- History is append-only. Each turn is written to a tape. The model reads a slice of that tape, not a chat array that grows without limit.
- Every step reports an event. Model calls and tool calls each report a start, an end, and a result. A host can watch a run, change the next input, or stop it.
- A tool is a function. A Python function with type hints is enough. Code mode lets the model write a short program that calls several tools in one step.
