Keep two things separate: use the Tape commands to see **what a session remembered**, and use OTLP / Logfire to see **how a turn ran**. Even without an external tracing backend, the agent still saves the selected conversation and run records. See [Events](/docs/concepts/events/) for the distinction between events, output streams, and persisted records.

## Prerequisites {#prerequisites}

- You have [installed the Bub application](/docs/getting-started/install/#app-install) and configured a working model.
- Docker or Podman is required to run Phoenix locally.
- Activate the [application virtual environment](/docs/getting-started/install/#app-install) before installing the tracing dependencies.

## Inspect the Tape {#inspect-tape}

```bash
bub run "What tools do you have, and what is each one good for?"
bub run ",tape.info"
```

Expected output is similar to:

```text
name: becda04eb9f7369c__065943a03cbe6395
entries: 98
anchors: 2
last_anchor: session/start
entries_since_last_anchor: 44
last_token_usage: 7458
last_token_cache_hit_rate: 72.50%
```

![A terminal screenshot showing `tape.info` output after a Bub task run](/docs/observability/tape-info.png)

| Field | Purpose |
|---|---|
| `entries` | How much history the session has accumulated |
| `anchors` / `last_anchor` | Number of anchors and the latest context boundary |
| `entries_since_last_anchor` | Whether a handoff is worthwhile to shorten the next prompt |
| `last_token_usage` | Usage recorded by the most recent model path, when available |
| `last_token_cache_hit_rate` | Share of prompt tokens served from cache in that same call, when the provider reports the detail |

Search for tool calls, errors, or handoffs:

```bash
bub run ",tape.search query=loop.step"
```

When you need the model to interpret the results, run a natural-language request (this depends on credentials):

```bash
bub run "Inspect the current tape and summarize what the last turn did."
```

See [Tape](/docs/concepts/tape/) for persistence and context selection rules.

## Export traces {#export-traces}

Export traces when you need to see model and tool timing, concurrency relationships, and error paths. Tape and telemetry are independent of each other.

### Arize Phoenix (local deployment) {#arize-phoenix}

```bash
docker run --rm --name bub-phoenix \
  -p 6006:6006 \
  arizephoenix/phoenix:latest
```

UI: `http://localhost:6006`.

Install the tracing dependencies:

```bash
# Source repository
uv sync --extra app --extra trace

# Or an installed distribution
uv add "bub[app,trace]"
```

The `trace` optional dependency includes the OpenTelemetry API/SDK and an HTTP/protobuf OTLP exporter. Installing the `logfire` optional dependency also includes the dependencies for `app` and `trace`; if both are installed, an **explicit OTLP endpoint still takes precedence**.

```bash
OTEL_SERVICE_NAME=bub \
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=http://localhost:6006/v1/traces \
OTEL_EXPORTER_OTLP_TRACES_PROTOCOL=http/protobuf \
bub run "What tools do you have, and what is each one good for?"
```

`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is the complete trace URL. You can also set `OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:6006` (the exporter appends `/v1/traces`); the trace-specific variable takes precedence. The default protocol is `http/protobuf`; configure headers, timeouts, resource attributes, and sampling with standard OTEL environment variables.

An explicit OTLP endpoint uses direct export, and Bub does not configure Logfire even if it is installed. Existing tracer providers are preserved; `OTEL_SDK_DISABLED=true` disables this initialization path. Authenticate with `OTEL_EXPORTER_OTLP_TRACES_HEADERS` (or `OTEL_EXPORTER_OTLP_HEADERS`); for a Phoenix project name, add `x-project-name=my-project`.

In Phoenix, open the default project, then the most recent trace, and look for `invoke_agent bub`, `chat <model>`, and `execute_tool <tool>`.

![A screenshot showing Bub GenAI telemetry exported to Phoenix through OTLP](/docs/observability/phoenix-otel.png)

### Pydantic Logfire {#pydantic-logfire}

When no explicit OTLP endpoint is set, the Bub CLI configures Logfire at startup (the `logfire` optional dependency must be installed).

```bash
unset OTEL_EXPORTER_OTLP_TRACES_ENDPOINT OTEL_EXPORTER_OTLP_ENDPOINT

# Source repository
uv sync --extra app --extra logfire

# Or an installed distribution
uv add "bub[logfire]"

logfire auth
logfire projects use
bub run "Inspect this repository and summarize its structure."
```

Set `LOGFIRE_TOKEN` in deployments. Look for `bub` on the Logfire Agents page. Subagents are nested under the tool span that launched them; runs in the same session are correlated through `gen_ai.conversation.id`.

### Embedding and span contents {#trace-contents}

Spans record model inputs and outputs, tool arguments and final results (after the result hook / spill), token usage, and errors; inline media is not uploaded. Model fallback updates the model attributes and records failed attempts as events. Token usage is written only on model spans.

Tape events such as loop steps, handoffs, and spills are attached to the current span; Tape metadata contains `trace_id` / `span_id`. When embedding, initialize explicitly:

```python
from bub.tracing import configure_otlp

configure_otlp()  # Reads OTEL_EXPORTER_OTLP_TRACES_ENDPOINT or OTEL_EXPORTER_OTLP_ENDPOINT
```

When these optional dependencies are missing, tracing is skipped. When you stop consuming a stream early, use `contextlib.aclosing(stream)` so the model stream, Tape branch, and span are closed. Cancellation closes the span and sets `bub.cancelled`.

Native spans provide the OpenInference classification and standard `gen_ai.*` attributes that Phoenix needs. If you still need to project **stored** Tape entries into spans, use the contrib [`bub-tapestore-otel`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-tapestore-otel); when migrating, install this page's `trace` or `logfire` optional dependency, set `BUB_TAPESTORE_OTEL_ENABLED=false`, and keep your existing Tape storage.

## Clean up {#cleanup}

Use `Ctrl+C` for a foreground Phoenix. If it is detached:

```bash
docker rm -f bub-phoenix
```
