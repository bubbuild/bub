---
title: Store conversation history in SQLite
description: Move Bub's Tapes from files to SQLite with a SQLAlchemy tape store plugin.
---

By default, Bub stores Tapes as JSONL files. With [`bub-tapestore-sqlalchemy`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-tapestore-sqlalchemy), the application can use SQLite or another SQLAlchemy database instead; `,tape.info`, `,tape.search`, Tape branching, and sidecars keep the same behavior.

This guide configures the global store used by the CLI. You can also construct `SQLAlchemyTapeStore` in your own Python program and pass it to `core.Agent`; see [Reuse the Bub app](/docs/sdk/reuse-app/).

:::caution
Switching storage does not migrate existing JSONL Tapes. After moving to a new database, old sessions do not appear in `tape.search` or the session list, though the original files remain in the `tapes/` directory under Bub home. If you need the old history, back it up and complete the migration before switching.
:::

## Before you begin {#before-you-start}

- [Install the Bub application](/docs/getting-started/install/#app-install) and confirm that `bub --help` works.
- Have a workspace where `bub run "What tools do you have?"` can call the model normally.
- Optional: the `sqlite3` command line for inspecting the database.
- Confirm that the current `BUB_HOME` points to the directory where you want to keep the database:

```bash
printf '%s\n' "${BUB_HOME:-$HOME/.bub}"
```

## 1. Install the plugin {#install}

```bash
bub install bub-tapestore-sqlalchemy@main
bub hooks
```

Confirm in the output that the plugin loaded:

```text
provide_tape_store: tapestore-sqlalchemy, builtin
```

Higher-priority implementations come first. Seeing `tapestore-sqlalchemy` means the plugin overrides the built-in file store; if only `builtin` appears, check whether the plugin was installed into the same environment that runs `bub`.

## 2. Configure the database {#configure}

The plugin uses this by default:

```text
<BUB_HOME>/tapes.db
```

This tutorial uses a file in the current directory instead, so it is easy to inspect and clean up:

```bash
export BUB_TAPESTORE_SQLALCHEMY_URL="sqlite+pysqlite:///$PWD/bub-tapes.db"
```

`sqlite+pysqlite` uses the SQLite driver from Python's standard library, so no extra driver is required. The URL must use SQLAlchemy's format; relative paths resolve against the process's current directory, which is why this uses `$PWD` to build an absolute path.

Optional settings:

| Variable | Default | Description |
| --- | --- | --- |
| `BUB_TAPESTORE_SQLALCHEMY_ECHO` | `false` | Print SQL for debugging |
| `BUB_TAPESTORE_SQLALCHEMY_CONNECT_ARGS` | `{}` | JSON object passed to `create_engine(connect_args=...)` |

Putting these variables in the workspace `.env` lets `bub` read them on every start. The plugin creates tables the first time it opens a database; if an existing database has an incompatible schema, it reports a clear error instead of attempting a migration.

## 3. Write and check the Tape {#verify}

Run a turn, then inspect the current Tape:

```bash
bub run "Reply with one short sentence: hello from SQLite."
bub run ",tape.info"
```

The output should include the Tape name, entry count, anchors, and token usage:

```text
name: 86774b31b96845a4__0b871d5e50e7c192
entries: 9
anchors: 1
last_anchor: session/start
entries_since_last_anchor: 8
```

The name and counts depend on your workspace and model. The key point is that `,tape.info` can read the session you just created, which shows that both writes and reads go through the new store.

Inspect the Tapes in the database:

```bash
sqlite3 "$PWD/bub-tapes.db" \
  "SELECT name, last_entry_id FROM tapes ORDER BY name;"
```

Inspect the anchors:

```bash
sqlite3 "$PWD/bub-tapes.db" \
  "SELECT entry_id, anchor_name, entry_date FROM tape_entries WHERE kind = 'anchor';"
```

`last_entry_id` is the highest entry ID allocated for each Tape. `tape_entries.payload` and `meta` store JSON; editing these columns directly bypasses Bub's Tape invariants and is not recommended.

## 4. Use another database {#other-databases}

The same plugin accepts any SQLAlchemy URL, but the environment that runs `bub` must have the corresponding dialect and driver installed. PostgreSQL, for example, requires an additional driver, and a remote database also needs connection parameters and network security configuration.

Validate a non-SQLite backend first with `,tape.info`, `,tape.search`, and a multi-step tool task:

- Whether entry IDs increase monotonically;
- Whether anchor queries return the correct rows;
- Whether concurrent writes conflict;
- Whether the Tape remains readable after a reconnect.

Default SQLite connections enable foreign key constraints and a 30-second busy timeout. The behavior of other drivers depends on the driver itself.

If you need dedicated SQLite vector search, see [`bub-tapestore-sqlite`](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-tapestore-sqlite).

## Cleanup {#cleanup}

```bash
unset BUB_TAPESTORE_SQLALCHEMY_URL BUB_TAPESTORE_SQLALCHEMY_ECHO BUB_TAPESTORE_SQLALCHEMY_CONNECT_ARGS
rm -f "$PWD/bub-tapes.db"
```

Deleting the database permanently loses the conversation history it contains. After removing the plugin or clearing `BUB_TAPESTORE_SQLALCHEMY_URL`, Bub returns to the default file store but does not automatically import the SQLite data.
