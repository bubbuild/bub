[Model Context Protocol](https://modelcontextprotocol.io/), or **MCP**, is an open protocol that lets Agents securely and consistently call external tools and data sources, whether local or remote.

By installing the [bub-mcp](https://github.com/bubbuild/bub-contrib/tree/main/packages/bub-mcp) plugin, you can seamlessly connect tools from across the MCP ecosystem to the Bub application.

## Get started {#get-started}

Before you start, [install the Bub application](/docs/getting-started/install/#app-install) and make sure [`uvx`](https://docs.astral.sh/uv/) is on `PATH`, since it launches [`mcp-server-time`](https://pypi.org/project/mcp-server-time/).

<Steps>

1. **Install the plugin**

   ```bash
   bub install bub-mcp@main
   bub hooks
   ```

   `bub install` resolves `bub-mcp@main` from [`bub-contrib`](https://github.com/bubbuild/bub-contrib). `bub hooks` should show:

   ```text
   load_state: builtin, mcp
   provide_channels: builtin, mcp
   register_cli_commands: builtin, mcp
   ```

   If `mcp` is missing, check whether the plugin was installed into the environment used by the current `bub`.

2. **Register the time server**

   `bub-mcp` reads server definitions from `~/.bub/mcp.json`; when `BUB_HOME` is set, it reads `$BUB_HOME/mcp.json` instead.

   ```bash
   mkdir -p ~/.bub
   cat > ~/.bub/mcp.json <<'EOF'
   {
     "mcpServers": {
       "time": {
         "command": "uvx",
         "args": ["mcp-server-time"]
       }
     }
   }
   EOF
   ```

   Configuration notes:

   - For local command-line servers (stdio), provide `command` and, optionally, `args` and `env`.
   - A configuration containing `command` automatically uses stdio, so no `transport` field is needed.

3. **Verify the connection**

   ```bash
   bub mcp list
   ```

   Expected output:

   ```text
   🔌 MCP Tools
   - time
     Status: Connected
     Tools: mcp.time_get_current_time, mcp.time_convert_time
   ```

   Note:

   - Each MCP tool is exposed to Bub as `mcp.<server>_<tool>`.
   - To reduce prompt token usage, Bub lazily loads full tool definitions by default. The model calls `tool.describe` to fetch a definition when needed. Set `BUB_MCP_DEFERRED_TOOLS=false` to include all definitions directly in the system prompt.

   If you see `Status: Disconnected`, first run `uvx mcp-server-time` outside Bub to diagnose startup problems, then press `Ctrl-C` to stop it.

4. **Call a tool in a turn**

   MCP tools are kept connected by `mcp.lifecycle`. `bub chat` and `bub gateway` start it; `bub run` does not.

   ```bash
   bub chat
   ```

   Wait a few seconds for the MCP handshake to complete, then enter:

   ```text
   What time is it in UTC right now?
   ```

   The model should call `mcp.time_get_current_time`. You can also call the tool directly without going through the model:

   ```text
   ,mcp.time_get_current_time timezone=UTC
   ```

   The first turn may begin before the tools are ready. If the model does not call the tool, check the connection with `bub mcp list`, then ask it explicitly to use the time tool.

</Steps>

For long-running deployments, use the [gateway](/docs/app/gateway/) or a [container](/docs/app/deploy/). For example, `bub gateway --enable-channel telegram` still starts `mcp.lifecycle` automatically unless `!mcp.lifecycle` is passed explicitly.

## Add other servers {#add-servers}

Append additional entries under `mcpServers`. HTTP and SSE use `url`, with optional `headers`:

```json
{
  "mcpServers": {
    "weather": {
      "url": "https://weather.example.com/mcp",
      "transport": "http"
    },
    "events": {
      "url": "https://events.example.com/mcp",
      "transport": "sse",
      "headers": { "Authorization": "Bearer token" }
    }
  }
}
```

Another stdio example, launching a filesystem server through `npx`:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  }
}
```

Put the allowed directories in `args` and pass credentials through `env`. After saving, run `bub mcp list` to check the connection.

### Manage with the CLI {#manage-cli}

You can also modify the same configuration with `bub mcp add`:

```bash
# stdio
bub mcp add --transport stdio time -- uvx mcp-server-time
bub mcp add --transport stdio --env API_KEY=secret example -- node ./my-server.js

# HTTP / SSE
bub mcp add --transport http weather https://weather.example.com/mcp
bub mcp add --transport sse --header "Authorization: Bearer token" \
  events https://events.example.com/mcp

# remove
bub mcp remove time
```

`--env` is only for stdio, and `--header` is only for HTTP or SSE.

## Use with portable plugins {#with-agent-plugins}

[Agent Plugins](/docs/integrations/agent-plugins/) can also carry MCP servers. The two configurations use separate lifecycle channels and tool names, so they can run at the same time without affecting each other.

## Troubleshooting {#troubleshooting}

| Symptom | What to check |
| --- | --- |
| `mcp` is absent from `bub hooks` | Reinstall the plugin in the environment where the current `bub` lives |
| `Status: Disconnected` | Run the `command` directly outside Bub, or access the `url` |
| `bub mcp add` prints `CancelledError` after writing | The entry may already be saved; verify with `bub mcp list` |
| The tool does not appear during a turn | Use `bub chat` or `bub gateway`, and confirm that `mcp.lifecycle` is not excluded |
| Permission denied on `mcp.json` | Confirm that `~/.bub/` is writable, or set `BUB_HOME` to a directory owned by the current user |
