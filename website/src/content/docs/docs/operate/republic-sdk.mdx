Bub uses Republic for every model request. Bub owns the agent loop, tools, hooks,
model selection/fallback, streaming UI and tape. This branch uses an **unreleased
local SDK baseline**; installing the old PyPI Republic package is insufficient.

## Install the required dependency

Use Python 3.12+ for Bub and place these two checkouts beside each other:

```text
workspace/
  republic-dev/       # Republic dev, accepted SDK rebuild
  bub-republic-dev/   # Bub feat/republic-provider-sdk
```

In Bub, `uv sync --locked --extra trace` installs its required dependency
`republic>=0.5.9.dev21,<0.6` from the repository-relative source `../republic-dev`.
The lock contains that relative source; no machine-specific path or unpublished
remote commit is required. `trace` is optional telemetry, not a model backend.
The removed SDK is not installed. Current source instructions require both checkouts.

For a wheel-only consumer installation, build both wheels, then install both
explicit paths in the same resolver operation. For example, in a fresh venv:

```bash
uv pip install --python /explicit/venv/bin/python \
  /explicit/path/to/bub-VERSION-py3-none-any.whl \
  /explicit/path/to/republic-VERSION-py3-none-any.whl
uv pip check --python /explicit/venv/bin/python
```

The Bub wheel declares a normal Republic dependency, without the local uv source.
The acceptance script below builds Bub, excludes the sibling source from exported
constraints and installs the supplied Republic wheel with all required dependencies.
Nothing here implies that these commits or wheels are available remotely.

## Configure the protocol

In your Bub YAML configuration, for an API-key Responses model:

```yaml
model: openai:your-responses-model
api_key: YOUR_EXPLICIT_API_KEY
republic_protocols:
  openai: responses
max_tokens: 16384
completion_args:
  temperature: 0.2
```

Use `BUB_REPUBLIC_PROTOCOLS='{"openai":"responses"}'` for the equivalent protocol
selection. API keys/base URLs retain scalar/per-provider `BUB_API_KEY` and
`BUB_API_BASE`, including `BUB_OPENAI_API_KEY`. Standard `OPENAI_API_KEY`,
`OPENROUTER_API_KEY` and `ANTHROPIC_API_KEY` are provider-specific defaults;
explicit Bub settings take precedence. IDs split at the first colon, so
`openrouter:vendor/model:free` retains the complete model ID.

| Model prefix | Protocol setting | Default endpoint |
| --- | --- | --- |
| `openai:` | `chat` (default) | OpenAI `/v1/chat/completions` |
| `openrouter:` | `chat` only | `https://openrouter.ai/api/v1/chat/completions` |
| `openai:` | `responses` | OpenAI `/v1/responses` |
| `anthropic:` | `messages` (default) | Anthropic `/v1/messages` |

| `openai:` | `codex` (or saved Bub login with no API key/base/protocol override) | `https://chatgpt.com/backend-api/codex/responses` |

An explicit `api_base` overrides API-key endpoints. Unsupported providers and
protocol combinations fail configuration; there is no alternate SDK path.
Onboarding offers OpenRouter, OpenAI, a custom OpenAI-compatible URL, and
Anthropic. It lists models with the official SDK and zero retries; model discovery
does not prove tool support or inference access. Codex selection skips API-key
discovery. Copilot/Grok login UX is not connected in Bub.

## ChatGPT/Codex login and existing credentials

`bub login openai` retains browser/local callback UX. `--manual --no-browser`
accepts a callback URL or a bare authorization code. URLs must contain the correct
state; Republic handles PKCE and OAuth exchange. Bub owns the manual-code UX.
Login writes the existing nested `tokens` format at `CODEX_HOME/auth.json`
(default `~/.codex/auth.json`). `--codex-home` selects the login directory; set
runtime `codex_home` / `BUB_CODEX_HOME` to match when using a custom directory.
Existing parseable auth.json files work directly. Reading does not write or move
the file, and there is no credential migration step.

Automatic Codex selection applies only to `openai:` without an explicit base URL
or protocol override. A normal API key uses the API path. A supplied access token
with a ChatGPT account claim selects Codex without a refresh token or known expiry.
With no explicit key/base, a parseable auth.json selects Codex; file existence or
a model name containing "codex" is insufficient. An explicit protocol map still
selects the requested protocol and permits explicit credentials/endpoint.

Bub preserves its prior expiry policy: stored `tokens.expires_at` (numeric or
RFC3339), then access JWT `exp`, then `last_refresh + 3600`, or current time plus
3600 when no hint exists. These last fallbacks are Bub freshness estimates, not
server guarantees. JWT claims are unverified routing/time hints. Republic does
not impose these policies. Bub refreshes 120 seconds early, before creating the
provider. If refresh fails, an unexpired old token remains usable; expired tokens
fail. A successful refresh updates the same auth.json, preserving unknown fields
and the prior account ID when no replacement is returned, then atomically writes
with mode 0600. Persistence failure stops inference after rotation. There is no
401 refresh/replay, login UI during inference or cross-process refresh locking.

Republic supplies auth/request mechanisms and accepts existing credentials.
Bub's default factory explicitly uses zero SDK retries; a custom factory can
choose its own transport policy. ChatGPT tokens are not general OpenAI API keys.
All login/inference/refresh evidence is synthetic fixtures; live account and
entitlement acceptance remain unverified. Copilot/Grok login UX is not connected.


## Request options

`completion_args` uses Republic's `RequestOptions` fields:
`temperature`, `top_p`, `stop`, `tool_choice`, `parallel_tool_calls`, and
`provider_options` for protocol-native options. `max_tokens` is Bub's setting and
becomes `max_output_tokens`; setting both is rejected. When unset, API-key protocols
use 16384; Codex omits it and rejects an explicitly supplied limit. Model/messages/tools/stream
and other adapter-managed overrides are rejected. `client_args` is unsupported.
The `reasoning_effort` tape setting maps to Chat's `reasoning_effort` or Responses/Codex
`reasoning.effort`; `auto` omits the option. Conflicting native options fail.
Anthropic requests default to ephemeral `cache_control`; an explicit native option
takes precedence. Anthropic thinking configuration goes in `provider_options`, not that tape flag.
Consult the matching protocol guide in the Republic checkout for allowed options.

Only text input and function tools/results are enabled in this Bub adapter.
Legacy image blocks and unsupported fields fail before HTTP; broader SDK media
support is not automatically Bub support. Output reasoning uses the existing UI
reasoning event; the complete native message is saved independently of display.

## Ownership, tools and fallback

`ModelRunner.run` constructs Republic `Request` data and consumes native events
and `Response` directly. Codex consumes one SSE request, with leading system
messages becoming `instructions`; it preserves native Responses history.

Each attempt owns and closes its provider/client. An embedding application can
override async `ModelRunner.create_provider(candidate)` and return an adapter
constructed with `client=your_official_async_client`. That client is borrowed:
its settings and configured retries are retained, and the caller
closes it after active calls. Bub closes the response and adapter on success,
failure, timeout, cancellation or consumer `aclose()`; early exit does not drain
or restart inference. Consumers must close streams they stop reading.

Only a completed `stop`/`tool_call` outcome can continue. Tool calls must have
original IDs/names, JSON-object arguments and a completed native item status when
present. Length limits, failed/incomplete results, malformed arguments and unknown
finish reasons produce an unsuccessful final event and execute no tools. Their
native terminal output is retained on tape with `context=false` for inspection,
excluded from the next model history. Transport interruption/cancellation keeps
the existing non-terminal behavior: no successful chat record or tool execution.

Bub's `ToolExecutor` runs accepted calls. Error/denial flags survive result hooks;
Anthropic receives `is_error`, while Chat/Responses receive explicit JSON result
data with `is_error: true`. Republic never executes tools or starts another round.
The Bub agent may explicitly advance its loop after tools, subject to `max_steps`.

Configured `fallback_models` remain Bub policy. A provider error before **any
native stream event** can try the next configured candidate. There is no fallback
after output, on invalid history/options or on an incomplete terminal outcome.
The default Bub factory explicitly disables SDK retries; each candidate then
issues one HTTP attempt. Republic adds no automatic refresh or agent loop.

## Durable history and compatibility

New message dictionaries add `_republic`, containing format `version: 1`, the
provider/protocol tag and the full serialized Republic `Message`. Tool-call tape
entries add `message`; tool-result entries add `messages`. Existing content/call/
result fields remain readable. A new process reconstructs native history from
the actual JSONL tape, including Responses item IDs/encrypted reasoning,
Anthropic thinking signatures and original tool call IDs. Usage and finish reason
are recorded with existing run events; native usage fields/raw data are retained.

Legacy text and complete function history remain readable. Extra legacy metadata,
missing tool identity or media are rejected instead of silently discarded. New
native history cannot be switched to another protocol. Start a new
tape or perform an explicit caller-owned migration. A hook cannot change only the
visible view of a native message: the view and native payload must agree, and the
SDK also checks native item consistency. Old Bub releases do not understand the
native envelope; do not use them to continue these tapes losslessly.

Tape write failures still propagate. Bub does not retry an already executed tool
when persistence fails. This is not a transaction or an exactly-once guarantee
for external effects if the process crashes between tool execution and persistence.

## Reproduce offline acceptance

From this Bub checkout, pass the exact wheel and full clean source commit:

```bash
python scripts/check_republic_wheel.py \
  /explicit/path/to/republic-VERSION-py3-none-any.whl \
  --source-commit 8c6531070b0ef2f22fba843e1cc46055d6e697a0
```

The script creates a new Python 3.12 environment with the trace extra, installs Bub non-editably and
Republic from that wheel under Bub's locked dependency constraints, runs
`uv pip check`, asserts the removed SDK is absent, verifies both imports resolve to site-packages and checks installed
Republic file contents against the selected archive. It records version, SHA256,
source commit and import locations in the printed temporary evidence directory.
No absolute dependency path is written to the project or lock.

The integration suite uses real official SDK methods and HTTPX transports with
synthetic HTTP/SSE fixtures. For Responses, Anthropic and Codex, separate Python
processes execute the real runner/tool/tape path: one model response requests a
tool, Bub executes it once and writes JSONL; the next process reads that file,
sends the retained encrypted reasoning or signature and gets the final answer.
Each process asserts one HTTP request, released resources and the same single
tool execution record. Tests also cover the actual agent loop, Chat/OpenRouter,
the complete synthetic Codex login/refresh flow, CLI/config, tracing, hooks, explicit fallback, tool failures, truncation, tape-write failure, early
close, cancellation, borrowed clients and unsupported inputs.

This evidence does not establish OAuth entitlement, login success, live model
availability or production endpoint compatibility. No real token file or account
is needed by the suite. Standard repository checks remain `make check`, `make test`
and `make docs-test`. Republic is required for test collection and runtime imports.

The accepted SDK runtime wheel is `0.5.9.dev21+g8c6531070`, source commit
`8c6531070b0ef2f22fba843e1cc46055d6e697a0`, SHA256
