This page is the complete hook interface reference. See [Application hooks](/docs/app/plugins/) for usage examples and [Turn](/docs/concepts/turn/#stages) for the order of stages.

## Reading conventions {#notation}

| Notation | Meaning |
| --- | --- |
| **First** | Calls implementations by priority and returns the first non-`None` result; `False`, `""`, and `[]` are results |
| **All** | Calls every implementation and collects return values; whether one failure affects the whole dispatch depends on the hook |
| **Sync** | Must be implemented synchronously; an awaitable return value skips that implementation and logs `hook.async_not_supported` |
| `Envelope` | `Any`. A mapping, dataclass, Pydantic model, or object with attributes is accepted |
| `TurnState` | `dict[str, Any]`, shared by hooks, tools, and events in this turn |

Hooks not marked “sync” may be implemented synchronously or asynchronously.

## Priority and dispatch {#priority-and-dispatch}

Bub uses pluggy to register implementations and `HookRuntime` to invoke them consistently.

| Rule | Description |
| --- | --- |
| Registration order | Builtin implementations (`builtin`), then plugins from `bub` entry points |
| Priority | `@hookimpl(tryfirst=True)` runs first; `trylast=True` runs last |
| Same priority | Later registrations run first |
| Actual traversal | Calls the reversed `get_hookimpls()` list |
| Argument injection | Selects arguments according to the implementation's `argnames`; declare only the parameters you use |
| Unsupported | `wrapper=True`, `hookwrapper=True` |

| Collector | Behavior |
| --- | --- |
| `call_first` / `call_first_sync` | Returns the first non-`None` result; empty containers and `False` count as results |
| `call_many` / `call_many_sync` | Collects every non-skipped result; whether failures propagate depends on the call path |

The plugin report shown by `bub hooks` displays pluggy registration order, not execution order. Use the priority rules and logs when diagnosing hook order.

## Turn hooks {#turn-hooks}

The following nine hooks are driven by `BubFramework.process_inbound()`.

| Hook | Signature | Dispatch |
| --- | --- | --- |
| `resolve_session` | `(message: Envelope) -> str` | First; a falsy result falls back to `channel:chat_id` |
| `load_state` | `(message: Envelope, session_id: str) -> TurnState` | All; merged from low to high priority |
| `build_prompt` | `(message, session_id, state) -> list[UserContent] \| LegacyPrompt` | First; a falsy result uses the inbound content |
| `run_model` | `(prompt, session_id, state) -> str` | First |
| `run_model_stream` | `(prompt, session_id, state) -> AsyncStreamEvents` | First |
| `continue_prompt` | `(prompt, tape: Tape, state: StreamState) -> str \| None` | First; called when `StepFinished.status == "continue"` |
| `save_state` | `(session_id, state, message, model_output) -> None` | All; called in the model stage's `finally` block |
| `render_outbound` | `(message, session_id, state, model_output) -> list[Envelope]` | All; returned batches are flattened and concatenated |
| `dispatch_outbound` | `(message: Envelope) -> bool` | All, once per outbound message; return values are ignored |

### Behavioral details {#turn-hook-details}

- `build_prompt` uses the **first non-`None` result**. If it is `""` or `[]`, the framework does not try later implementations and instead falls back to the inbound content.
- Non-dictionary values returned by `load_state` are ignored. `save_state` is called whether the model succeeds, fails, or is cancelled, provided execution has entered the model stage.
- Implement either `run_model` or `run_model_stream`. Text results can be converted to streams, and streams can be collected into text. After replacing the model stage, the builtin Agent's interception hooks do not run automatically.
- Model hooks are selected by plugin priority; `tryfirst` / `trylast` still apply within the same hook.
- `continue_prompt` returning `None` continues the conversation directly without adding a user message. It receives `StreamState`, not `TurnState`.
- If every `render_outbound` result is empty or contains only empty batches, the Framework creates one reply from `model_output`, reusing the inbound `channel` and `chat_id`.
- A `dispatch_outbound` implementation cannot prevent other implementations through its return value; filter during `render_outbound` instead.

`process_inbound()` ultimately catches errors from all Turn hooks, calls `on_error(stage="turn", ...)`, and re-raises them. A missing implementation in the model stage itself or an error reported within a stream uses `stage="run_model"`.

### Prompt content {#prompt-content}

`build_prompt` returns `list[UserContent]`:

| Element | Construction |
| --- | --- |
| Text | `str` |
| Image | `republic.image(url, media_type=...)` |
| Audio | `republic.audio(url, media_type=...)` |
| Video | `republic.video(url, media_type=...)` |

Hooks that receive legacy-format prompts (`run_model`, `run_model_stream`, `continue_prompt`, and `system_prompt`) receive:

| Situation | Form |
| --- | --- |
| No media | `str` |
| Contains media | A list of `[{"type", "media_type", "url"}]` content blocks |

Legacy strings and content-block lists are still accepted and converted by `to_content()`; use `bub.prompt.to_legacy_prompt()` to convert back to the legacy form.

## Application hooks {#application-hooks}

The following 14 hooks manage configuration, resources, channels, and tools rather than belonging directly to a message's Turn.

| Hook | Signature | Dispatch |
| --- | --- | --- |
| `register_cli_commands` | `(app: typer.Typer) -> None` | All, sync |
| `onboard_config` | `(current_config: dict) -> dict \| None` | All, sync; a non-dictionary result raises `TypeError` |
| `provide_model_options` | `(session_id, workspace: Path \| None) -> ModelOptions \| None` | All; merges model lists and keeps the first `current_model` |
| `provide_environment` | `(session_id, workspace: Path) -> Environment \| None` | First; cached per session and closed when `running()` exits |
| `on_error` | `(stage: str, error: Exception, message: Envelope \| None) -> None` | All; observer exceptions are logged and skipped |
| `system_prompt` | `(prompt, state) -> str` | All, sync; joins non-empty results with blank lines from low to high priority |
| `provide_tape_store` | `() -> TapeStore \| AsyncTapeStore \| None` | First, sync; may return a generator |
| `provide_lifespan` | `() -> Iterator[None] \| AsyncIterator[None] \| None` | All, sync; enters every generator as a context manager |
| `provide_tape_sidecar` | `() -> TapeSidecar` | All, sync; deduplicates by `name`, keeping the highest priority |
| `provide_channels` | `(message_handler) -> list[Channel]` | All, sync; deduplicates by `name`, keeping the highest priority |
| `build_tape_context` | `() -> TapeContext` | First, sync; a result that is not a `TapeContext` raises `TypeError` |
| `admit_message` | `(session_id, message, turn: TurnSnapshot) -> AdmitDecision \| None` | First; `None` uses the channel's default scheduling |
| `provide_tools` | `() -> list[Tool]` | All, sync; deduplicates by `name`, keeping the highest priority |
| `provide_steering_inbox` | `() -> SteeringInbox \| None` | First, sync; may return a generator |

### Return types and invocation timing {#application-hook-details}

- `onboard_config` receives the loaded configuration plus modifications from earlier implementations; its returned dictionary is merged back. `collect_onboard_config()` handles plugin-name filtering.
- `provide_model_options` supplies candidates only. The caller decides whether to display them and how to persist the current model.
- `provide_environment` is used for `bash`, file tools, and code execution. Without a provider, the builtin implementation returns `LocalEnvironment`.
- Multiple `system_prompt` results do not overwrite one another; a higher-priority implementation can only append its own block.
- `provide_tape_store` is resolved once inside `framework.running()`. Outside that scope, `get_tape_store()` returns `None`.
- `provide_lifespan` must return a synchronous or asynchronous generator that yields once. Failure to enter one prevents the entire scope from starting.
- None of the three resource providers accepts an object decorated with `@contextmanager` / `@asynccontextmanager`; the runtime treats it as an ordinary value.
- The `message_handler` passed to `provide_channels` is an async `(message) -> None`. Implementations must return a list of channels, not a single channel.
- `admit_message` only decides how to handle a new message; it does not create tasks. `ChannelManager` executes the effects of `process`, `drop`, `follow_up`, and `steer`.
- `provide_tools` may provide the same tool name more than once. The highest-priority implementation wins, and other tools with that name are ignored.
- `on_error` is an observer interface. It cannot prevent the original exception from propagating; failure of an implementation only logs `hook.on_error_failed`.

Common `stage` values for `on_error`:

| `stage` | Source |
| --- | --- |
| `turn` | Uncategorized exceptions within a Turn, including prompt, model-stage, and reply handling |
| `run_model` | No model implementation, or an error reported in the stream |
| `resolve_session` | Session resolution failed before channel admission |
| `admit_message` | Channel admission failed |

When `admit_message` returns an `AdmitDecision`, `ChannelManager` handles the new message according to its `action`:

| `action` | Session has a running Turn | Session is idle |
| --- | --- | --- |
| `process` | Schedules a new Turn immediately, allowing concurrency | Schedules a Turn immediately |
| `drop` | Drops the message | Drops the message |
| `follow_up` | Queues it for FIFO processing after the current Turn | Schedules a Turn immediately |
| `steer` | Steers the current Turn; moves the message to the pending queue if it cannot be injected or consumed in time | Schedules a Turn immediately |

Steering adjusts the current task, while queueing adds follow-up work. `provide_steering_inbox` provides the holding boundary for steering messages, and `MessagesPending` delivers them to the Agent.

### Runtime resources {#runtime-resources}

`framework.running()` acquires resources in this order:

1. Enters every generator returned by `provide_lifespan`.
2. Acquires the result of `provide_tape_store`.
3. Acquires the result of `provide_steering_inbox`.

On exit, it closes session execution environments and releases these resources in reverse order; cleanup also runs on exception paths.

| Scenario | Scope |
| --- | --- |
| `bub run` | One message |
| `bub chat` / `bub gateway` | The entire application runtime |
| Embedded host | Determined by the host; should cover the service lifecycle |

- Providers that need cleanup should return generators and release connections in `finally`.
- `save_state` handles application state only, not resource cleanup.
- Multiple `running()` scopes should not overlap on the same Framework.
- Background shell process-tree termination: POSIX sends `SIGTERM` and then `SIGKILL`; Windows terminates only the direct shell. The host must still clean up when it forcibly kills processes.
- A sidecar's physical Tape name is `<main tape>__sidecar__<sidecar>`; it follows the main Tape through forks, merges, archives, and resets. Removing a provider does not delete existing data.

#### Application errors {#runtime-errors}

`on_error` observes framework errors within this scope. It is not a recovery mechanism and does not change exception propagation. An embedding host should catch exceptions raised by `process_inbound()` itself. Unhandled CLI exceptions usually exit with a non-zero status, but `bub run` only logs some model-stage errors and returns fallback text, in which case it may still exit with `0`.

## Agent interception hooks {#interception-through-pluginagenthooks}

`AgentPlugins` subscribes to Agent events and invokes these four hooks. They can also be connected directly through [`PluginAgentHooks`](#pluginagenthooks).

| Hook | Signature | Dispatch |
| --- | --- | --- |
| `before_llm_call` | `(request: LLMCallRequest, state) -> LLMCallRequest \| LLMCallDecision \| None` | Chained; a replacement request continues, while `finish(text)` terminates |
| `after_llm_call` | `(request, result: LLMCallResult, state) -> None` | All |
| `before_tool_call` | `(call: ToolCall, state) -> ToolCallDecision \| None` | Chained; `replace` or `deny` terminates |
| `after_tool_call` | `(call, result: ToolCallResult, state) -> None` | All; implementations share the same mutable result |

### Control semantics {#interception-semantics}

- After `before_llm_call` returns a modified `LLMCallRequest`, later implementations see the new value. Use `dataclasses.replace()` to create a copy of the frozen dataclass.
- `LLMCallDecision.finish(text)` skips the model provider and uses `text` directly as model output. It does not trigger `after_llm_call`.
- `ToolCallDecision.proceed(arguments)` modifies arguments and continues; `replace(result)` and `deny(message)` skip the tool and stop later interception implementations.
- Exceptions from interception implementations are logged as `hook.agent_hook_failed` and skipped. An exception does not block a tool call; return a decision to do that.
- An incorrect return type logs `hook.agent_hook_bad_return` and skips that implementation.
- `after_llm_call` and `after_tool_call` cover success and ordinary exception failures. Cancellation and consumer stream closure do not trigger them.
- `after_tool_call` also receives denied and replaced calls. Assigning to `result.result` changes the result seen by the model; `result.error` retains the original error.

### Payload fields {#interception-payloads}

| Type | Fields |
| --- | --- |
| `LLMCallRequest` | `run_id`, `model`, `messages`, `tool_names`, `max_tokens` |
| `LLMCallResult` | `run_id`, `text`, `tool_calls`, `usage`, `error`, `duration_ms` |
| `LLMCallDecision` | `action="finish"`, `text` |
| `ToolCall` | `run_id`, `tool`, `arguments`, `context` |
| `ToolCallResult` | `run_id`, `tool`, `arguments`, `result`, `error`, `duration_ms` |
| `ToolCallDecision` | `action` (`proceed` / `replace` / `deny`), `arguments`, `result`, `message` |

`LLMCallRequest` exposes only tool names and cannot add or remove tools. Change the tool set in `Agent.prepare_tools()` or the application's tool policy.

### PluginAgentHooks {#pluginagenthooks}

`PluginAgentHooks` converts Agent events into the hooks above:

| Agent event | Hook |
| --- | --- |
| `LLMCallStarted` | `before_llm_call` |
| `LLMCallFinished` | `after_llm_call` |
| `ToolCallStarted` | `before_tool_call` |
| `ToolCallFinished` | `after_tool_call` |

Direct EventBus handlers and interception hooks have different exception policies:

| Item | Interception hook | EventBus handler |
| --- | --- | --- |
| Exceptions | Logged and skipped | Propagated to the `emit()` caller |
| Control | Returns a decision | Modifies event fields |
| Execution order | Determined by pluggy priority | Handler registration order |

`PluginAgentHooks.subscribe(events)` connects the adapter to an existing or new bus. `AgentPlugins.attach(agent)` subscribes automatically and connects `continue_prompt`, the steering inbox (`SteeringInbox`), and system prompts to the Agent.
