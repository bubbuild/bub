This page covers common `core.Agent` constructor parameters and run options. For a complete example, see [Run an agent in Python](/docs/sdk/).

## Choose a model {#choose-a-model}

`Agent(model=...)` sets the default model, and `agent.run(model=...)` overrides it for the current run only. A run that needs a model raises `ValueError` when neither supplies one.

The caller manages the Republic model's lifetime:

```python
async with republic.get_model(
    "openai:gpt-5-mini", api_key="...", api_base="https://example.test/v1"
) as model:
    agent = Agent(model=model)
    async with agent.run("Hello", tape="example", options={"max_tokens": 4096}) as stream:
        async for event in stream:
            print(event.kind, event.data)
```

`options` are the Republic chat options passed to each model call, such as `max_tokens`. The agent adds the tools for the current Step. The core SDK does not read `BUB_*` configuration; supply model credentials through Republic's arguments or its environment variables.

To implement your own fallback, credential selection, or timeout policy, implement `bub.core.ModelClient`:

| Member | Contract |
| --- | --- |
| `spec` | Read-only default `provider:model` string. |
| `max_tokens` | Default output token limit, or `None`. |
| `open_stream(messages, *, spec, options)` | Async context manager yielding `(provider_name, republic_stream)`. |

`messages` is a list of `republic.Message` objects, and `options` contains the current Step's tools. A `LLMCallStarted` handler can rewrite `request.model`. With a Republic chat model, a change within the same provider reuses the existing client; a change across providers creates a client configured from Republic's environment. Implement a custom `ModelClient` for any other policy.

## Pass text and media {#multimodal-input}

`prompt` is a list of content items that can mix strings with Republic image, audio, and video objects:

```python
async with agent.run(
    [
        "Describe the main problem shown in this screenshot.",
        republic.image("https://example.com/error.png", media_type="image/png"),
    ],
    model=model,
    tape="ui-review",
) as stream:
    ...
```

Local files can be read as bytes, with an explicit MIME type:

```python
from pathlib import Path

image = republic.image("image/png", data=Path("error.png").read_bytes())
```

Use `republic.audio()` and `republic.video()` for audio and video, respectively. Bub passes media to the model and saves serializable message structures; it does not transcode or compress media for you. The formats, sizes, and modalities actually supported depend on the model provider. See [Tape and media](/docs/concepts/tape/#media) for the boundaries of media records in a tape.

## Compose the system prompt {#system-prompt}

`system_prompt` accepts text, a function, or an ordered collection of both. Functions receive a `PromptContext` and may return a string synchronously or asynchronously. The agent renders the sections before each model Step, ignores empty results, and joins the rest with blank lines.

```python
from bub.core import PromptContext


@agent.system_prompt.add
def customer(context: PromptContext) -> str | None:
    if (name := context.state.get("user")) is not None:
        return f"You are helping {name}."
    return None
```

`PromptContext` provides:

| Field | Contents |
| --- | --- |
| `prompt` | The current Step's new user content; an empty list when continuing the conversation. |
| `tools` | Tools offered to the model for the current Step. |
| `available_tools` | All tools registered with the agent, without per-Step filtering. |
| `model` | Current model identifier. |
| `tape` | Tape for the current run. |
| `state` | State shared by this turn, that is, `tape.context.state`. |
| `agent` | Current agent. |

`agent.system_prompt.remove(section)` removes a section. The supplied `state` is not persisted automatically; see [Tape and state](/docs/concepts/tape/#state) for how to restore it across runs.

## Distinguish Bub tools from provider tools {#provider-tools}

Objects passed to `Agent(tools=[...])` come in two kinds:

```python
from republic.tools import WebSearch

agent = Agent(tools=[add_tool, WebSearch()])
```

- `add_tool` is a Bub `Tool`, executed by Bub in the host process with events, rendering, and concurrency control, and stored in `agent.tools`.
- `WebSearch()` is a Republic provider tool, sent with the request for the model provider to execute, and stored in `agent.builtin_tools`.

Provider tools do not pass through Bub's `ToolExecutor`, so Bub's tool interception, deferred loading, and code mode grouping do not apply to them. Available tools and behavior depend on Republic and provider support.

## Constructor parameters {#agent-options}

The table below lists the common parameters. For the complete parameter list, defaults, and type contract, see the [Python API](/docs/reference/python-api/#agent).

| Parameter | Default | Purpose |
| --- | --- | --- |
| `model` | `None` | Republic chat model or `ModelClient`. |
| `store` | A new `InMemoryTapeStore` | Synchronous or asynchronous Tape storage. |
| `tools` | `()` | Bub tools and provider-executed tools. |
| `system_prompt` | `()` | Text or callable sections rendered per Step. |
| `context` | `default_tape_context()` | Selection policy for turning Tape entries into model messages. |
| `command_prefix` | `None` | Text command prefix; once set, tools can be called directly. |

`agent.tools` stores `Tool` objects by name, and `agent.builtin_tools` stores provider tools. `max_tool_concurrency` does not control concurrency between different Runs; the host must coordinate that.

## Advanced run control {#advanced-run-control}

The following entry points are for cases where you need to control the agent loop yourself. For normal runs, the constructor parameters above and `agent.run()` are enough.

### Choose tools per step {#customize-how-a-step-is-prepared}

When you need to filter tools by business rules, subclass `Agent` and override `prepare_tools(tape, prompt)`. The default implementation offers the supplied tools and excludes only those marked `exposure="command"`; `tape.context.state` is the state for this turn.

### Add messages during a run {#pending-messages}

Steering adds new messages to the current Run, while queueing leaves messages for a later Turn. `MessagesPending` and `StepFinished` provide the entry point for the former; the application's `follow_up` admission decision handles the latter. For CLI usage, see [Steer a running agent](/docs/app/terminal/#steering).

| Event | When | Usage |
| --- | --- | --- |
| `MessagesPending` | A step builds its request; the last allowed step has not been reached and there are no tool calls. | Append user content to `event.messages`; if there are new messages when the step ends, the run continues. |
| `StepFinished` | A step ends. | Set `next_prompt` when `status == "continue"`; `None` continues the conversation directly. |

```python
from bub.core.events import MessagesPending, StepFinished

inbox: dict[str, list[str]] = {}


@agent.events.on(MessagesPending)
def send_queued(event: MessagesPending) -> None:
    event.messages.extend([text] for text in inbox.pop(event.tape.name, []))


@agent.events.on(StepFinished)
def check_results(event: StepFinished) -> None:
    if event.status == "continue":
        event.next_prompt = ["Check the tool results before answering."]
```

No further `MessagesPending` event is emitted after the last allowed step. If the run still needs to continue, it ends with a `max_steps_reached` error.

### Manage the Tape and steps yourself {#manual-runs}

`agent.session(name, state=...)` opens a Tape branch whose lifecycle you manage. Pass the returned `Tape` object to `run_on()` or `run_once()`:

- `await agent.run_on(tape, prompt, model=...)` starts the full model loop and returns a stream that the caller must close.
- `agent.run_once(prompt, model=..., tape=tape)` yields a single model Step, which is useful when you implement the loop yourself.

Both accept a `Tape` object, not a tape name.
