Bub has four concepts. A **turn** carries one message through the app. A **tape** stores the conversation. **Events** report what the loop does. An **extension point** is a place where new behavior goes. Your own Agent and the Bub app use all four.

Read the pages in any order. Each page starts with the short answer, then the details.

## Layers

`core.Agent` takes a model, tools, prompt sections, and a tape store. You pass these components in yourself, so a small Python service needs only the core dependencies.

`BubAgent` adds the app defaults: settings, skills, commands, tool selection, and steering. `BubFramework` manages plugins, message processing, and outbound routing around it. Use these parts when you want the behavior they provide.

`pip install bub` installs the kernel. `pip install "bub[app]"` installs both layers. The [installation guide](/docs/getting-started/install/) explains the dependency choices.

## Terms

An **Agent** runs the model and tool loop. A **run** is one `agent.run()` call, and it can contain several **steps**. A **step** is one model call and the tools that it asks for. A **turn** is one inbound message and the run that answers it.

A **tape** stores the conversation. Its **entries** are messages, tool calls, results, and events. An **anchor** marks the point where the context starts. A **handoff** writes a new anchor. The turn's **state** is a separate dictionary that tools and handlers share.

The app adds three parts. **Plugins** provide Python hooks. **Skills** provide written instructions. **Channels** carry messages in and out.

## Design notes

The kernel does not read settings or plugin hooks. Hooks belong to the app: a plugin implements them, and `BubFramework` calls them. The core therefore works the same in both layers.

History and context stay separate. The tape keeps every entry. The context selects the entries that the next model call reads. An anchor starts a new context and keeps the earlier entries, so you can read the full history and still send a short request.

Each part has one job. A tool performs an action. A skill describes a procedure. A channel connects the app to a place where people work. These roles stay separate, so you know which part to change.
