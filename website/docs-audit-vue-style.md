## 1. 信息架构：Guide vs API

| 层 | 目的 | 读法 | 内容密度 |
|---|---|---|---|
| **指南 Guide** | 按问题讲“为什么 → 怎么用” | 顺序读 | 故事流；先 80% 场景，再进阶 |
| **API 参考** | 完整、可检索的词条 | 跳读/查字典 | 类型 → 详细信息 → 示例 → 参考链接 |
| **快速上手 / 教程 / 示例** | 低摩擦上手 | 可选路径 | 简介页明确分流 |

侧栏分层（config）：开始 → 基础 → 深入组件 → 逻辑复用 → 内置 → 规模化 → 最佳实践 → TS → 进阶。API 按全局 / 组合式 / 选项式 / 内置 / SFC / 进阶分桶。

**Bub 映射**：概念页走 Guide 叙事；CLI/配置/类型签名走 API 词条；别把完整参数表塞进入门页。

## 2. 开篇模式（到第一段代码前有几句）

实测：

- **简介**：1–2 句定义 + 一句能力边界 → 立刻最小示例（约 2–3 句后出码）。
- **创建一个应用**：H1 后几乎无导语，第一节标题下 **1 句** 就出 `createApp`。
- **响应式基础**：页首一句“本页含两种 API 风格”→ 小节下 **2–3 句** 说明意图 → 代码。
- **API 词条**：一句功能说明 → **类型** → **详细信息** → **示例**（几乎无散文铺垫）。

规则：**先一句话说明“这是什么 / 解决什么”，尽快给最小可运行片段**；不要用半页背景才出码。

## 3. 同一页如何同时服务初学者与高手

1. **主线只讲当前概念**；细节、边界、深层机制用链接推到后文/API/进阶（“后续章节会讲”“先别急”）。
2. **声明前提**（如需 HTML/JS），并给补课链接；不假装零基础也能硬啃框架。
3. **双轨示例**（选项式 / 组合式）并排或可切换，核心概念声明为共享。
4. **按角色分流**：“如果你是初学者… / 如果你是有经验的开发者…” 各给一条路径。
5. **进阶块后置**（caveats、性能、与外部系统集成），主路径保持顺读。
6. 首次阅读时，**少链到会打断心流的深链**；若必须链，说明“第一次读是否需要点开”。

## 4. 刻意避开的反模式

来自 Writing Guide + 中文页实操：

- **套话 / 权威口号**：不说“最佳实践所以该用 X”，用具体问题与例子证明。
- **循环复述**：不把同一句换措辞再说一遍；用链接代替大段重复。
- **一次塞多个新概念**（文+码同时引入两套新东西）。
- **标题写解法不写问题**（差：“使用 props”；好：“用 Props 向子组件传递数据”）。
- **滥用 tip/warning 盒子**；每页 tip/caveat 不宜超过约 2 个；相邻两个 alert 视为失败信号。
- **否定读者吃力**：“很简单”“显然”“只需”。
- **空洞概括 + 无代码**：Show, don’t tell。
- **示例过抽象**（`ComponentA`）；优先具体、可共鸣（`BlogPost`、待办树）。
- **中文侧**：直译英文语序、夹带无信息的完句填充词、中英空格/标点混乱、术语前后不一。

## 5. Bub 中文文档可执行清单

### 结构

- [ ] 页面是 **Guide**（顺序叙事）还是 **API**（词条）？两者版式不要混。
- [ ] Guide：问题 → 最小例子 → 解释 → 边界/进阶链接。
- [ ] API：一句话功能 → 类型/签名 → 详细信息 → 示例 → 互链指南。
- [ ] 侧栏按“功率/成本比”排序：先高频刚需，后niche。

### 开篇与节奏

- [ ] H1/小节后 **≤3 句** 出现第一段代码（概念页）；API 词条可 **1 句**。
- [ ] 一次只引入一个新概念；下一概念用新小节。
- [ ] 代码后用 **短列表** 点出刚看到的 1–2 个要点，不另起长散文复述。

### 读者分流

- [ ] 页首声明前提知识（若有）。
- [ ] 初学者主路径可独立读完；专家细节用链接/后置小节。
- [ ] 需要“两种写法”时并排示例，并写明共同点。

### 文风（中文）

- [ ] 标题描述 **问题/任务**，不是 API 名堆砌。
- [ ] 用语具体、短句；避免“赋能”“最佳实践”空话。
- [ ] 不用“简单/显然/只需”；用“你 / 我们”，不用“您”。
- [ ] 术语前后一致；专有 API/品牌按约定保留英文（参考 Vue 译法表精神：统一表驱动）。
- [ ] 中英文之间空格；全角 `，。；：！？`；括号用半角 `()`；行内代码用反引号。
- [ ] 代码、注释、docstring、system prompt 和日志按示例场景选择语言，不机械中文化；真实 SDK 与跨语言插件可使用自然英文。
- [ ] 先问题后方案；用例子证明取舍，不堆 tip 盒。
- [ ] 优先互链，避免多页复制同一大段说明。

### 改写自检（删改时）

- [ ] 删掉对理解无增益的开场白与同义反复。
- [ ] 每个小节能否回答：“为什么要关心 → 怎么做 → 下一步去哪”。
- [ ] 若出现第三个 tip/警告：改为独立“注意事项”小节或链到参考页。

## 附：中文译写习惯（摘自译须，Bub 可对齐）

- 应用（不写“应用程序”）、开发者、其他、举例来说。
- 关联词可补（然而 / 并且 / 只要…就…）让逻辑更顺，但勿注水。
- 调整为中文语序；省略仅服务英文句式的虚词。
